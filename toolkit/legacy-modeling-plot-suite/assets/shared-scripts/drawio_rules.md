# DrawIO 绘图规范

Claude 生成 DrawIO 技术路线图/流程图/架构图时参考此文件。

## 工具链

- `draw.io.exe`（已打包在 `runtime/draw.io/`，PATH 已注入）
- 导出：`draw.io.exe --export --format pdf --crop --output figures/xxx.pdf figures/xxx.drawio`
- ⛔ 必须加 `--crop` 裁剪白边

## ⛔ 零容忍规则（CLI headless 导出踩坑总结）

1. **禁止 `shadow=1`**：CLI 导出时 shadow 导致节点不渲染
2. **禁止 XML 注释 `<!-- -->`**：浪费 token，可能导致解析错误
3. **禁止特殊形状**：`shape=callout` 等在 CLI 导出不稳定，全部用标准 `rounded=1` 圆角矩形。例外：`shape=mxgraph.arrows2.arrow` 可用于过渡箭头（已验证 CLI 导出正常）
4. **换行用 HTML**：`html=1` 模式下用 `&lt;br&gt;` 换行，所有节点必须有 `html=1`。⛔ 包括 edge 上的标签文字节点（如判断分支的"是/否"标签）——如果标签的 value 里包含 `&lt;font&gt;` 等 HTML 标签但 style 里没有 `html=1`，导出后会显示原始 HTML 代码而不是渲染后的文字
5. **ID 全局唯一**，不能重复
6. **XML 转义**：`<>&"` → `&lt;&gt;&amp;&quot;`
7. **每个 edge 必须有子元素**：`<mxGeometry relative="1" as="geometry"/>` 不能自闭合
8. **中文直接写 UTF-8**
9. **页面背景透明**：`mxGraphModel` 加 `background=none`，并设 `page="0"` 去掉页面边框，避免导出 PDF 有灰色背景
10. **架构图/变量关系图用 TikZ 而非 DrawIO**：CLI 导出不支持 ELK 自动路由，`orthogonalEdgeStyle` 的连线会穿过中间节点。需要精确连线路由、数学公式、几何图形的图继续用 TikZ
11. **图内不写标题**：标题由 LaTeX `\caption{}` 统一管理，DrawIO 图内不要放标题文字节点（避免标题重复、字体不一致）
12. **⛔ 技术路线图：研究方法卡片(右栏)绝对不画横跨连线到中栏/左栏**。横跨连线必然穿过中栏大内容框，draw.io CLI headless 导出没有 ELK 路由，会把这种线画成歪歪扭扭的折线（已知顽疾）。正确做法：研究方法卡片与它对应的阶段/内容**保持同一 y（水平对齐）**，靠位置表达对应关系，不需要任何连线。同理左栏阶段节点也不要向中栏画横跨连线。**只保留两类连线**：左栏阶段之间的竖直主流程粗箭头、中栏同一行相邻内容框之间的短水平连线（这两类两端对齐且中间无障碍，不会歪）。
13. **⛔ 中栏内容框逐行居中**：研究内容列的每一行内容框集合，必须在中栏宽度内**水平居中**。特别注意一行只有 1-2 个框时（如单独的"结论"/"汇总"框），必须居中摆放（行中心 = 中栏中心），**不能左对齐到第一列**。计算：单框居中时 `x = 中栏中心 - 框宽/2`；多框一行时整体跨度居中。

## ⛔ 通用设计规范（所有 DrawIO 图必须遵守）

以下规范适用于所有类型的 DrawIO 图（技术路线图/流程图/框架图/指标体系图等）。

### 容器与层次

- **用 swimlane 容器表示阶段/分组**：每个逻辑阶段用 `swimlane` 容器包裹，有标题栏+淡色背景。子节点用 `parent="容器id"` + 相对坐标
- **不同阶段用不同配色**：容器背景色交替使用淡蓝/淡黄/淡绿/淡紫/淡红，形成视觉层次
- **容器标题栏**：`startSize=22`，字号 11px，加粗，写明"第N阶段：阶段名称"

### 节点设计

- **节点内容要丰富**：主标题（加粗 9-10px）+ 灰色副标题（8px，`color:#666`），用 `<br>` 换行。不要只写一个词
- **关键/核心节点突出**：用加粗边框（`strokeWidth=2.5`）+ 浅色填充（如 `fillColor=#e1d5e7`）+ ★ 前缀标记
- **结论/结果节点**：用特殊填充色（绿色 `#d5e8d4` 表示通过，红色 `#f8cecc` 表示稳健）+ ✓ 标记
  - ⛔ **结果节点只写"做什么/得到什么量"的定性步骤，禁止写具体求解结果数值**。技术路线图/流程图是画**方法与步骤**的框架，不是结果展示区（具体数值属于结果图表和正文）。
    - ✅ 正确：`求解得到临界时刻 t*`、`输出最优螺距 p_min`、`时间二分求根（精度 1e-6 s）`（算法参数属方法，可留）
    - ❌ 错误：`输出：t*=412.473838 s`、`p_min=45.033745 cm`、`误差=7.01e-8`（完整精度结果值不许进节点——既喧宾夺主，又常与正文精度对不上、连带触发数字溯源审计）
- **负面/异常节点**：用红色边框（`strokeColor=#b85450`）标注，如"虹吸效应""普通面板回归"
- **普通节点**：白底 + 阶段主色边框（`fillColor=#FFFFFF;strokeColor=阶段色`）

### 连线规范

- **用 source/target 属性连线**：`edge="1" source="n1" target="n2"`，不要用手动坐标点。DrawIO 会自动计算连接位置
- **同容器内连线**：`parent="容器id"`，连线颜色与容器主色一致
- **跨容器过渡箭头**：`parent="1"`，用粗灰色（`strokeWidth=4;strokeColor=#C0C0C0;endArrow=block;endFill=1;endSize=8`）
- **决策分支**：是/否标签用对应颜色（绿色=是，红色=否），标签紧贴箭头

### ⛔ 连线路由规则（7 条，防止连线穿过节点）

1. **禁止多条边共享同一路径**：如果两条边连接同一对节点，必须从不同位置出入。用 `exitY=0.3` 和 `exitY=0.7` 区分，不要都走 0.5
2. **双向连接用对侧**：A→B 从 A 的右侧出（`exitX=1`），进 B 的左侧（`entryX=0`）；B→A 反过来
3. **必须显式指定 exitX/exitY/entryX/entryY**：每条边的 style 里都要写这 4 个属性，不要让 DrawIO 自动猜
4. **连线必须绕开中间节点**：画边之前先看源和目标之间有没有其他节点挡着，有的话用 waypoints 绕行，留 20-30px 间距
5. **先规划布局再画线**：把节点按流向分层/分列排好，留出连线通道（150-200px 间距），再画边
6. **复杂路由用多个 waypoints**：一个拐点不够就用 2-3 个，形成 L 形或 U 形路径，每个方向变化都需要一个 waypoint
7. **连接点选自然方向**：上下流向从底部出（`exitY=1`）顶部进（`entryY=0`）；左右流向从右侧出（`exitX=1`）左侧进（`entryX=0`）。不要用角落连接点（如 `exitX=1,exitY=1`）

**画完后自检**：有没有边穿过非源/目标的节点？有没有两条边重叠？有没有用了角落连接点？

### 整体布局

- **画布宽度 920-950px**：内容区足够宽，节点不挤
- **容器间距 15-17px**：过渡箭头占据这个间距
- **节点宽度 130-220px**：根据文字长度调整，中文节点 ≥ 字数×14+40px
- **节点高度 28-48px**：单行 28px，双行（主标题+副标题）40-48px
- **同行节点等距分布**：计算容器宽度，均匀分配
- **⛔ 节点必须居中分布**：如果一行只有 3 个节点但容器宽度能放 4 个，节点要居中排列，不要左对齐留大片空白。计算方法：`左边距 = (容器宽度 - 节点总宽度 - 节点间距总和) / 2`。最后一行（结论/输出）尤其容易出现左对齐问题，必须检查

### 配色方案（swimlane 容器）——柔和科研风格

⛔ 颜色要低饱和度、柔和淡雅，像 Nature/Science 论文里的配图风格。不要用高饱和度的鲜艳色。

| 阶段序号 | 容器填充 | 容器边框 | 标签填充 | 节点边框 | 适合内容 |
|---------|---------|---------|---------|---------|---------|
| 1 | `#F0F4FA`（雾蓝） | `#C8D6E8` | `#5B7FA5` | `#7B9FC0` | 背景/问题/输入 |
| 2 | `#F5F0E8`（暖米） | `#DDD4C0` | `#9A8A6A` | `#B0A080` | 数据/指标/构建 |
| 3 | `#EDF5ED`（薄荷） | `#C0D8C0` | `#5A8A5A` | `#7AAA7A` | 分析/检验/探索 |
| 4 | `#F0ECF5`（淡藤） | `#C8BCD8` | `#7A6A9A` | `#9A8AB0` | 核心模型/建模 |
| 5 | `#F5EDED`（浅玫） | `#D8C0C0` | `#9A6A6A` | `#B08080` | 稳健性/检验 |
| 6 | `#EDF0F5`（银灰蓝） | `#C8D0D8` | `#6A7A8A` | `#8A9AA8` | 结论/建议 |

节点配色原则：
- 普通节点：白底（`#FFFFFF`）+ 阶段色边框，边框宽度 1.5px
- 核心/高亮节点：极淡填充（阶段色加白 50%）+ 阶段色边框 2.5px
- 结论/通过节点：极淡绿填充（`#E8F0E8`）+ 绿边框
- 负面/失败节点：极淡红填充（`#F5E8E8`）+ 红边框
- 连线颜色：与阶段色一致但稍深，宽度 1.5px
- 过渡箭头：中灰（`#B8B8B8`），宽度 4px

⛔ 节点数量控制：每个阶段/容器内最多 2 行节点，每行最多 4 个。总节点数不超过 30 个。宁可精简也不要塞太多——杂乱比简洁更差。

## 布局模板参考（不强制，可自由发挥）

以下模板是参考起点，鼓励根据具体论文内容自由发挥布局和视觉设计。可以直接用模板、混合模板元素、或完全自创布局，只要遵守上面的零容忍规则和通用设计规范即可。同一用户的不同论文，技术路线图风格应有变化。

**⛔ 模板选择规则：现有 4 个技术路线图模板，每个都适用于所有论文类型（竞赛/统计建模/学术）。生成时**随机选一个**，确保同一用户的不同论文风格有变化。**


### 模板 B：简版四阶段（example_roadmap_stats）

三栏结构：粉色表头 + 薄荷绿六边形阶段 + 浅蓝内容模块 + 虚线框分组。适合阶段较少（3-4 个）、内容紧凑的研究。

**布局结构**：
- 顶部：三个表头（研究阶段 | 研究内容 | 研究方法），粗箭头向下引导
- 左列：六边形阶段节点（提出问题 → 分析问题 → 建模预测 → 政策建议），粗灰色箭头连接
- 中列：虚线框包裹每阶段的内容模块
- 右列：方法节点列出每阶段使用的具体方法
- 横向连接：阶段→内容（空心箭头），内容→方法（虚线箭头）

**配色（B 冷色版）**：粉表头 #F5D5E0 / 薄荷绿六边形 #B4D4D0 / 浅蓝子节点 #DAE8FC / 浅黄输出 #FFF2CC / 浅紫特殊 #E1D5E7

**配色（B-warm 暖色版）**：浅橙表头 #FCE5BD / 浅紫六边形 #C9B6DC / 暖橙子节点 #FFE6CC / 暖紫方法 #C9B6DC

### 模板 C：完整六阶段（example_roadmap_hex）

模板 B 的扩展版，6 个阶段（提出问题→分析问题→模型构建→实验验证→结果分析→结论与展望），每阶段 6-7 个子节点。适合内容丰富、需要展示完整研究链条的论文。

**布局结构**：
- 顶部：三个表头（研究阶段 | 研究内容 | 研究方法）
- 左列：6 个六边形阶段节点纵向排布
- 中列：每阶段一个虚线框，内含 4-7 个内容子节点（含横向小箭头连接）
- 右列：每阶段对应一个方法节点（多行说明该阶段的方法/工具）

**配色（C 冷色版）**：粉表头 #F5D5E0 / 薄荷绿六边形 #B4D4D0 / 浅蓝子节点 #DAE8FC / 薄荷绿方法 #B4D4D0

**配色（C-cool 高对比版）**：浅蓝表头 #CFE0F2 / 深蓝六边形 #7FB3D5 白字 / 浅紫子节点 #E1D5E7 / 暖橙方法 #E8A858 白字

**适用场景**：所有论文类型，特别适合内容丰富、阶段层次清晰的研究。

### ⛔⛔⛔ 三栏固定坐标铁律（技术路线图必须严格遵守，否则会歪斜）

三栏路线图最常见的毛病：**右列方法块每行左右错位（不在一条竖线上）、中列内容框没对齐表头中心**。
根因是每个块的 x 坐标各写各的。必须用「固定列坐标」——同一列的所有块共用同一个 x 和 width：

| 列 | 表头几何 | 该列所有块的 x | 该列所有块的 width |
|----|---------|---------------|-------------------|
| 研究阶段（左）| x=40, w=140（中心 110）| 阶段六边形 **统一 x=40** | 160 |
| 研究内容（中）| x=220, w=540（中心 490）| 内容大框/虚线框 **统一 x=220** | **统一 540** |
| 研究方法（右）| x=800, w=140（中心 870）| 方法块 **全部统一 x=800** | **全部统一 140** |

铁律：
1. **研究方法列**：所有方法块（m1/m2/m3/...）的 `x` 必须**完全相同**（如 800）、`width` 必须**完全相同**（如 140），只允许 `y` 变化。这样它们才会落在同一条笔直竖线上。**绝对禁止**给不同方法块写不同的 x（哪怕差 10px 也会肉眼可见地歪）。
2. **研究内容列**：所有内容大框/虚线框的 `x` 和 `width` 必须统一（如 x=220, width=540），其水平中心（490）必须等于「研究内容」表头的水平中心。框内子卡片在框内左右对称分布、留白均等。
3. **三个表头**的水平中心必须分别对齐其下方整列内容的中心（左 110 / 中 490 / 右 870）。
4. 改内容时**只改 value 文本，不要改这些固定的 x/width 坐标**——直接套用示例模板的坐标骨架，逐块替换文字即可。

⛔ **完整 XML 示例**：_utils/example_roadmap_stats.drawio、_utils/example_roadmap_stats_warm.drawio、_utils/example_roadmap_hex.drawio、_utils/example_roadmap_hex_cool.drawio。生成前先随机选一个 cat 出来参考其 XML 结构，然后替换为实际论文内容。


## 实践检查清单


生成每张 .drawio 后必须逐条自检：

- [ ] **字号检查**：最小字号 ≥ 10px，普通节点 ≥ 11px，标题 ≥ 12px
- [ ] **重叠检查**：相邻节点边界框不交叉，间距 ≥ 8px
- [ ] **对齐检查**：同行节点 y 坐标一致，同列节点 x 坐标一致
- [ ] **⛔ 列对齐铁律（三栏路线图必查）**：研究方法列**所有方法块 x 与 width 完全相同**（在一条笔直竖线上，不允许任何一行偏移）；研究内容列**所有内容框 x 与 width 相同**，且其中心对齐「研究内容」表头中心；三个表头中心分别对齐各自列内容的中心
- [ ] **连线遮挡检查**：无连线穿过节点或文字
- [ ] **文字溢出检查**：节点完全包含文字，中文节点 width ≥ 字数×14+30px，英文节点 width ≥ 字符数×8+30px。⛔ 如果节点内有换行（`<br>`），height 需要额外加 16px/行
- [ ] **样式一致性**：同类节点 fillColor/strokeColor/fontSize 统一
- [ ] **容器检查**：子节点 parent 指向正确的容器 id，坐标是相对坐标
- [ ] **edge 检查**：每个 edge 有 `<mxGeometry relative="1" as="geometry"/>`
- [ ] **无 shadow**：确认没有 `shadow=1`
- [ ] **无 XML 注释**：确认没有 `<!-- -->`
- [ ] **html=1 检查**：所有 mxCell（包括 edge 标签节点）的 style 里都有 `html=1`。如果 value 包含 `&lt;font&gt;`/`&lt;b&gt;`/`&lt;br&gt;` 但没有 `html=1`，导出后会显示原始 HTML 代码
- [ ] **紧凑度**：阶段间过渡箭头间距 ≤ 15px，整图不要拉得太长
- [ ] **填充度**：子分组框/节点必须填满层宽度，不留大片空白。两个分组框之间间距 15px
- [ ] **居中检查**：每行节点数少于容器能容纳的最大数量时，节点必须居中分布，不要左对齐。特别检查最后一行（结论/输出阶段）
- [ ] **尺寸控制**：DrawIO 图不需要限制高度，LaTeX 插入时用 `keepaspectratio` + `height` 双约束自动处理。专注于内容完整、节点不遮挡即可

## 技术路线图 vs 求解流程图（⛔ 必须区分）

| | 技术路线图 | 求解流程图 |
|---|---|---|
| 视角 | 全局——整篇论文从问题到结论 | 局部——单个子问题从输入到输出 |
| 内容 | 多个阶段，每阶段多个节点，展示整体求解思路 | 一个问题的具体步骤、判断分支、数据流向 |
| 放置 | 问题重述章节末尾 | 各子问题章节开头 |
| 数量 | 整篇论文 1 张 | 每个子问题 1 张 |

**布局不限制**——Claude 可以根据具体赛题内容自由发挥布局和视觉设计（纵向/横向/混合/分区/嵌套都可以），只要遵守：
1. 零容忍规则（无 shadow、无 XML 注释、无特殊形状等）
2. 通用设计规范（swimlane 容器、source/target 连线、双行节点、阶段配色）
3. 连线路由规则（不穿过节点、显式指定 exitX/exitY）
4. 图内不写标题（由 LaTeX caption 管理）

⛔ 唯一的硬限制：技术路线图和求解流程图不能长得一样——技术路线图要体现"全局多阶段"的视觉层次，求解流程图要体现"单问题步骤链"的逻辑流向。

### ⛔ 求解流程图最低要求（不能只画一条直线）

求解流程图必须体现问题求解的逻辑复杂性，不能只是一串节点从上到下排列。最低要求：

1. **至少 1 个判断分支**（菱形节点 + 是/否标签）——如"数据是否满足正态性？"、"模型精度是否达标？"、"约束是否满足？"
2. **至少 1 处并行/分叉**——如数据预处理和特征工程同时进行，或两种方法对比后选优
3. **节点双行**——主标题（加粗）+ 灰色副标题（具体方法/参数说明）
4. **循环反馈**（如果有）——参数不满足→调整→重新求解的回路箭头
5. **颜色区分步骤类型**——输入（蓝色）、处理（绿色）、判断（黄色）、检验（紫色）、输出（红色）

参考示例布局：主流程纵向排列，遇到判断分支时左右分叉（是→继续主流程，否→右侧替代方案或调整参数后回路），颜色按步骤类型区分（输入蓝/处理绿/判断黄/检验紫/输出红）

**⛔ 求解流程图绝对不要画右侧工具/方法注释栏**（"工具与方法"那种独立侧栏是技术路线图专属）。求解流程图应该简洁，只展示求解步骤和逻辑分支，**禁止**在右侧放 pandas/matplotlib/SciPy/numpy 等工具标签。

**⛔ 也不要把工具/库名（如 SciPy minimize、Python DEAP、scikit-learn 等）写进节点副标题。** 副标题只描述**步骤本身做什么**（输入/输出/方法的物理或数学含义），不写技术实现。例子：
- ❌ 错：「优化圆弧半径比 / SciPy minimize」
- ❌ 错：「需求热力分析 / scikit-learn KDE」
- ✅ 对：「优化圆弧半径比 / 最短路径目标函数」
- ✅ 对：「需求热力分析 / 核密度估计识别热点」

⛔ **完整 XML 示例**：`_utils/example_flow.drawio` 是一个可直接导出的完整求解流程图示例（有分叉、判断、循环反馈）。生成前先 `cat _utils/example_flow.drawio` 参考其 XML 结构和样式。

## 技术路线图生成流程

### Step 1: 读取规划文档确定内容

```bash
cat PROBLEM_ANALYSIS.md 2>/dev/null || cat TOPIC_PLAN.md 2>/dev/null || cat PAPER_PLAN.md 2>/dev/null
```

### Step 2: 确定阶段结构

典型科研论文技术路线图 3-5 个阶段：
- 提出问题（背景/假设/数据）
- 分析问题（指标构建/探索性分析/模型选择）
- 解决问题（核心模型/效应分解/稳健性检验）
- 研究成果（结论/政策建议）

### Step 3: 生成 .drawio XML

按三栏布局生成，用 swimlane 容器 + 相对坐标。

### Step 4: 导出 PDF

```bash
draw.io.exe --export --format pdf --crop --output figures/fig_roadmap.pdf figures/fig_roadmap.drawio
```

### Step 5: 验证 PDF 非空

```bash
ls -la figures/fig_roadmap.pdf
```

如果导出失败，检查：shadow=1？XML 注释？特殊形状？ID 重复？标签未闭合？
