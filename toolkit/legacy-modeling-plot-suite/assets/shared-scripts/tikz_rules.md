# TikZ 架构图生成规则

Claude 生成 TikZ 架构图时参考此文件。模板是起点不是终点，鼓励根据具体研究内容自由发挥布局和视觉设计。但下面标注 ⛔ 的低级错误必须避免。

## ⛔ TikZ 适用范围（先判断再画）

TikZ 擅长：流程图、技术路线图、变量关系图、算法流程图（带公式）、因果路径图、网络拓扑图、指标体系图。

**⛔ 以下场景不要用 TikZ，改用 GPT Image 或 DrawIO：**
- 复杂 3D 场景（圆柱体透视、球面反射、多层空间结构）→ 用 GPT Image
- 写实物理/工程场景（无人机、传感器、交通场景、建筑物）→ 用 GPT Image
- 简单的分层/分组/树形结构（无公式、无跨层连线）→ 用 DrawIO（更快更稳）

**TikZ 的优势场景（用 TikZ）：**
- 需要 LaTeX 公式渲染的图（如 $\Delta f < \epsilon$）
- 需要精确控制连线路径的图（跨层箭头+标注系数）
- 变量关系/因果路径图（三角/菱形布局+路径系数）
- 简单 2D 平面几何示意图（三角形、圆、坐标系、角度标注、虚线辅助线）
- 算法流程图（带判断分支和公式）
- 网络拓扑图（≤15 节点）

## 布局模板参考（不强制，选最合适的或自创）

`figure_style_guide.md` 中提供了多种布局模板作为参考。
`tikz_examples_extra.tex` 中提供了 15 个参考模板（A-O）：
- 架构类：A 神经网络(MLP)、H CNN卷积层堆叠、I Transformer模块化架构、L PINNs物理信息网络
- 评价/状态类：B 蛛网/雷达图、C 状态自动机
- 数学/物理类：D 函数图像、E 向量场/相平面、F 力学受力分析、G 光学光路、J 几何示意(三角形/重心)、M 线性规划可行域图
- 技巧/特殊：K 装饰路径(弹簧/波浪)、N 3D曲面(需 tikz-3dplot)、O 电路图(需 circuitikz)

### ⛔ 赛题特征 → TikZ 图类型触发表（数模/科研规划时优先按此选）

TikZ 在"数学符号 + 精确几何"类图上是天花板。遇到下列赛题特征时，**应主动规划对应的 TikZ 图**（这些图 DrawIO 画不了、matplotlib 画得笨拙）：

| 赛题/研究特征 | 应规划的 TikZ 图 | 参考模板 |
|--------------|----------------|---------|
| 线性/整数/非线性规划、优化求解 | 可行域图（约束线+可行域+等高线+最优解） | M |
| 微分方程、动力系统、稳定性分析 | 相平面图 / 向量场 | E |
| 物理力学（受力、斜面、桥梁、约束反力） | 自由体受力分析图 | F |
| 光学（成像、反射折射、激光） | 光路系统图 | G |
| 几何证明、平面几何、向量分解 | 几何示意图（calc） | J |
| **纯几何计算 / 多步几何推导**（建坐标系→角度递推→弦长/距离→交点/临界几何，如螺线排布、覆盖宽度、几何最优） | **几何推导构造图**：主图画坐标系+已知量+关键辅助线/角度/投影，**分步标注中间量**（$\theta_i$、$L_i$、$\Delta\varphi_i$、$r=b\theta$…），把"怎么一步步推出来的"用几何构造呈现；步骤多时主图+局部放大 inset | J（几何示意）扩展 |
| 函数拟合、收敛过程、灵敏度曲线 | 函数图像（公式刻度与正文统一） | D |
| 神经网络/深度学习/集成模型架构 | MLP / CNN / Transformer | A/H/I |
| 物理约束建模、PINN、算子学习 | PINNs 架构图 | L |
| 弹簧振子、机械连接、波动/阻尼 | 装饰路径片段嵌入物理图 | K |
| 电路网络、信号系统（电工杯等） | 电路图（circuitikz） | O |

**⛔ 规划提醒**：以前的规划只在"神经网络/变量关系/带公式算法流程"几类触发 TikZ，导致可行域、相平面、受力图、光路图这些 TikZ 最能打的类型被漏掉。现在凡命中上表特征，赛题分析阶段就应在 FIGURE_MANIFEST 里规划对应 `tikz_xxx` 图。

### ⛔ 技术路线图必须按论文类型选模板，同类型内随机（禁止每篇都用同一个）

技术路线图有 3 种风格模板（模板 4/9/10），**先按论文类型筛选可用模板，再在可用模板中随机选一个**。

#### 按论文类型选模板

| 论文类型 | 可用模板 | 选择方法 |
|---------|---------|---------|
| 经管实证/统计建模/社科 | 模板 4 或 模板 9 | 标题字符数为奇数→模板4，偶数→模板9 |
| 数据科学/ML/单问题竞赛 | 模板 4 | 固定用模板 4 |
| 竞赛多问题（3+子问题） | 模板 4 | 固定用模板 4（蓝灰色系，简洁清爽） |
| CS/AI/工程类 | 模板 9 或 模板 10 | 标题字符数为奇数→模板9，偶数→模板10 |

#### ⛔ 模板与论文类型的硬性约束

- **竞赛论文（所有竞赛类型）固定使用模板 4**（虚线框+双色节点，蓝灰色系）。模板 4 简洁清爽，最适合竞赛论文的学术风格
- **模板 10（管道+并行分支）不适合纯经管实证**（没有多模型对比的论文不要用并行分支）
- **模板 9（卡片分层）不适合竞赛多问题**（竞赛多问题应该用模板 4 的虚线框分组）

| 研究类型 | 推荐布局 | 模板编号 |
|---------|---------|---------|

| 经管实证/统计建模/社科 | 纵向虚线框+双色节点 | 模板 4 |

| 模板 | 视觉特征 | 适合场景 | ⛔ 不适合 |

| 模板 4 | 虚线框+双色节点，简洁清爽 | 通用，阶段清晰的线性研究 | — |
| 模板 9 | 圆形编号+卡片+方法/工具双层 | 方法论丰富的实证研究 | 竞赛多问题 |

**使用方式**：
- 可以直接用模板，改文字和数量
- 可以混合多个模板的元素（比如模板 9 的彩色竖条 + 模板 10 的并行分支）
- 可以完全自创布局，只要遵守下面的 ⛔ 规则
- 一篇论文可以混用多种布局，让图表更丰富
- **同一用户的不同论文，技术路线图风格应该有变化**

**配色规则：自由搭配，但要精致（竞赛论文除外，见下方竞赛配色规则）**

⛔ 不要每篇论文都用 `blue!80 + teal!70`。demo 文件里的配色只是示例，实际生成时必须根据论文主题自由搭配。

**所有配色方案都遵循模板 4 的浅色原则**：主节点 `fill=主色!6`（极浅）+ `draw=主色!80`（中等边框）+ 子节点 `fill=white` + `draw=辅色!70`。不要用深色填充。

**6 套配色方案**（按论文主题选，同一用户不同论文换着用）：

| 方案 | 主色（边框+箭头） | 主色填充 | 辅色（子节点边框） | 适合主题 |
|------|-----------------|---------|------------------|---------|
| A 学术蓝 | `blue!80` | `blue!6` | `teal!70` | 竞赛、通用、工程 |
| B 森林绿 | `green!70!black` | `green!5` | `teal!60` | 环境、生态、农业 |
| C 暖灰棕 | `brown!70` | `brown!5` | `orange!50` | 经管、社科、教育 |
| D 靛蓝紫 | `indigo!70` | `indigo!5` | `violet!50` | 医学、心理、生物 |
| E 青灰色 | `cyan!70!black` | `cyan!5` | `gray!50` | CS、AI、数据科学 |
| F 石板灰 | `gray!70` | `gray!4` | `gray!50` | 数学、物理、理论 |

**使用方法**：把模板 4 的样式定义里的颜色替换即可，结构不变：
```latex
% 方案 B 森林绿 示例
main/.style={..., draw=green!70!black, fill=green!5, ...},
sub/.style={..., draw=teal!60, fill=white, ...},
bigarrow/.style={-stealth, line width=1.4pt, color=green!70!black},
```

**⛔ 禁止的配色**：
- `red!80`、`orange!80`、`violet!80` 等高饱和暖色做主色 — 太刺眼
- 主节点 `fill=主色!30` 以上 — 太深，文字看不清
- 每个节点不同颜色 — 彩虹效果

**选色建议**（不强制，可以自创）：
| 论文主题 | 推荐方案 |
|---------|---------|
| 经管/金融 | 方案 A 或 C |
| 医学/健康 | 方案 D |
| 环境/生态 | 方案 B |
| 工程/CS | 方案 A 或 E |
| 社科/教育 | 方案 C |
| 数学建模竞赛 | 根据赛题主题从 A-F 中选 |
| 数学/物理 | 方案 F |

**⛔ 竞赛论文配色规则**：竞赛论文从 6 套配色方案（A-F）中根据赛题主题自由选择。例如生态类赛题用方案 B 森林绿，经济类用方案 C 暖灰棕，医疗类用方案 D 靛蓝紫。同一篇论文内所有 TikZ 图必须用同一套配色。不要每个问题换一个颜色，不同问题通过虚线框分组区分。

### ⛔ 几何示意图配色专用规则（受力图 / 光路图 / 螺线 / 可行域 / 相平面 / 函数图像等）

**⛔ 6 套架构图配色方案是为"节点 + 框图 + 箭头"设计的，几何示意图（曲线 + 标注点 + 角度 + 公式）不能直接套用！** 几何示意图的配色逻辑完全不同：

**几何示意图的颜色铁律（不论赛题主题）**：

| 元素 | 配色 | 例 |
|---|---|---|
| **主曲线/主形**（螺线、弧线、椭圆、可行域边界）| `blue!70!black` 或 `black` | `\draw[blue!70!black, line width=1.2pt] (..) -- (..)` |
| **辅助线**（虚线坐标、参考线、网格、对称轴）| `gray!50, dashed` | `\draw[gray!50, dashed] (0,0) -- (5,0)` |
| **关键点**（最优解、交点、节点）| 实心 `\fill[black]` 或 `\fill[red!70!black]`（≤ 3 个时用红强调）| `\fill[black] (A) circle (1.5pt)` |
| **次要点**（轨迹点、采样点）| 实心 `\fill[gray!70]` 或开口圆 `circle (1pt)` | `\fill[gray!70] (P) circle (1pt)` |
| **所有文字/数字/公式/标签**（坐标、角度、距离、符号、步骤名、$P_i$、$L$、$\Delta\varphi$…）| ⛔**一律纯黑 `black`**（要低调可 `black!85`，**禁止低于 !80**）| `\node[above] {$P_1$}`、`\node[font=\bfseries] {$L^*$}` — **黑色加粗**表强调，不靠变色 |
| **可行域 / 光照区域填充** | `fill=blue!10, fill opacity=0.4`（区域可半透明，但**区域内不能有文字**）| `\fill[blue!10, fill opacity=0.4] (..) -- (..) -- cycle` |
| **箭头**（向量、力、方向）| `black, -{Stealth[length=4pt]}`，**唯一例外**：表示外部驱动/力时可用 `red!70!black` | `\draw[->, thick, red!70!black] (O) -- (F)` |

**总颜色数硬上限**：**≤ 3 种**（含黑灰）。例如黑（主曲线/文字）+ 灰（辅助线）+ 红（关键点强调）。**禁止 4 种以上颜色**——这是"彩虹几何图"的成因。

**⛔⛔【铁律·所有 TikZ 图通用】文字与数字一律纯黑色，彩色只给"非文字"图形元素**：
- ✅ 可用彩色的：**线条 / 曲线 / 箭头 / 关键点标记(圆点) / 区域填充** —— 这些是"图形"，用色区分主辅/强调是对的。
- ⛔ **禁止彩色的：任何文字、数字、公式、符号($P_i$、$L$、$\theta_i$、$\Delta\varphi$)、步骤标题、坐标轴标签、图例文字** —— **全部 `black`（或 `black!85`）**。
- **强调怎么办**：靠**黑色加粗**(`font=\bfseries`)、字号、加框，**绝不靠把字变红/变蓝**。反例 `\node[color=spkey]{$L$}`、`\node[color=spmain]{①建系}` ❌ → 正例 `\node[black]{$L$}`、`\node[black,font=\bfseries]{①建系}` ✅。
- 原因：彩色文字在黑白打印/复印下辨识度差、显杂乱、不像正式论文；黑字配彩色线条才是学术图的干净观感。

**⛔⛔【铁律·带 `fill=` 的节点(图例框/说明框)设文字色必须用 `text=black`，绝不裸写颜色名】**：
- TikZ 里裸颜色名(`black`/`red`…)等价于 `color=`，会**同时设描边和填充**。当节点已有 `fill=<浅色>`、后面又跟一个裸 `black`(想设文字色)，裸色会把浅填充**覆盖成黑填充**，加上文字也是黑 → **整块渲染成一条纯黑块，图例文字全看不见**。这是"图例框变黑块"的唯一根因。
  - ❌ 反例：`\node[draw=gray!40, fill=gray!8, font=\footnotesize, black, inner sep=4pt]{图例}` —— 裸 `black` 覆盖 `fill=gray!8` → 黑块。
  - ✅ 正例：`\node[draw=gray!40, fill=gray!8, font=\footnotesize, text=black, inner sep=4pt]{图例}` —— `text=black` 只设文字色，不碰填充。
- **判据**：只要节点选项里有 `fill=<非 none>`，就**禁止**在其后出现裸颜色名；要黑字一律写 `text=black`。无 `fill=` 的纯标注节点(如 `\node[black]{$P_i$}`)不受此限（裸 black 只设 draw/text，无填充可覆盖）。`tikz_check.sh` 已加此项 CRITICAL 检测。

**⛔【默认单张图，多子图/序列图仅"必要时"用】**：一道推导题**首选一张几何构造图**说清（主图+分步中间量标注即可）。**只有当推导步骤多到一张图会挤糊、或阶段跳跃大（建系→约束→递推→临界是彼此独立的画面）时**，才拆成"多面板序列图"（横排/2×2 小面板+箭头串推导流）。⛔ 能一张说清就不拆；拆了每个子面板仍守上面全部规则（文字黑、≤3 色、不遮挡）。

**⛔ 流程图/技术路线图/几何推导图：只展示方法与逻辑，不标"求解结果数值"**（与 DrawIO/HTML 引擎同一红线）：
- 结果量用**符号**表达"得到什么"（`$t^*$`、`$L^*$`、`$p_{\min}$`、$\theta_i$），**禁止写算出来的具体结果值**（如 `t^*=412.473838`、`p_{\min}=45.03cm`）。
- ✅ **可标**：题目**给定的常量**（螺距 55cm、板长、初速、$k=10^4$ 等题设，来自原题、可追溯、恒定）、几何坐标/角度/距离（图本身的数学内容）、算法收敛精度/迭代设定等方法参数。
- ⛔ **不可标**：**代码求解算出的结果数值**——因为 `tikz_*.tex` 里手写的数字**没有任何溯源闸**（facts_audit 只扫 `*.py` 与 `main.tex/md`，不扫 tikz 源码），手敲进去一旦与正文/`results.json` 不符也查不出来，是最易脱节的三不管地带。
- **定位**：推导/几何图讲清"方法怎么来的、几何关系是什么"（评委看的是逻辑严谨性，符号足够）；具体算出多少交给数据图/结果表/正文（那里有 `results.json` 溯源闸）。这也符合国奖论文实际做法——推导图干净的符号+构造，不堆结果数。

**⛔ 几何示意图禁止项（按用户实战图复盘）**：

1. **禁止用红色做普通几何标注**（如"弦长 = ..."）。红色只保留给**关键点标记/线条本身**（最优解圆点、关键交点、强调曲线）——⛔ **红色绝不用在文字数字上**（强调变量的字也用黑色加粗，见上方文字铁律）
2. **禁止低 opacity 文字**——公式说明不能用 `opacity=0.3` 淡化（评委看不清直接扣分）
3. **禁止把多个标签堆在同一焦点附近**——比如 `节点 i`、`节点 i+1`、`弦长` 三个标签都贴在小圆点上：**必须用引线分散**：

```latex
% ❌ 反例：三个标签贴在 (0,0) 附近，重叠成一团
\fill (0,0) circle (1.5pt);
\node[above] {节点 $i$};      % 在 (0, 0.3)
\node[below] {节点 $i+1$};    % 在 (0, -0.3) — 跟点几乎重叠
\node[right] {弦长 $L$};      % 在 (0.3, 0) — 也挤在一起

% ✅ 正例：引线把标签拉到空白区域
\fill (0,0) circle (1.5pt);
\node (P1) at (0,0) {};
\draw[gray!60, thin] (P1) -- ++(-0.8, 0.6) node[above left, font=\footnotesize] {节点 $i$};
\draw[gray!60, thin] (P1) -- ++(0.8, -0.6) node[below right, font=\footnotesize] {节点 $i+1$};
\node[above=8pt of P1, font=\footnotesize] {弦长 $L$};
```

4. **禁止远端标签独立飘在角落**（如"盘入方向"独立放在右上角不连任何元素）：必须用引线 `\draw[gray!60, thin, ->] (text) -- (target)` 明确指向对应曲线段

5. **⛔【铁律·零容忍】说明文字分两条路——短图例留图下窄 `\parbox`，长公式/多行说明一律进正文，两者都严禁塞进图内**：

   - **图内**：**严禁**用 `\node at (锚点)` 把说明框摆到图内任意角落（尤其相对锚点如 `at (S.north east)`、`at (root.north)`）——宽说明框会压住主体节点造成遮挡。
   - **图下 `\parbox`（仅限极简图例）**：只放"关键符号定义/单行图例"，**≤ 2 行、宽度 ≤ 主图宽度**（如 `\parbox{0.55\textwidth}`，⛔ **禁用 0.85~0.92 这种满宽 parbox**）。放在 `tikzpicture` 之后、`\caption` 之前，居中。
   - **⛔⛔ 长公式推导 / 多行参数说明 / 成段文字 → 一律写进论文正文**（图正下方的文字段），**绝对不焊进 tikz 图文件**。原因：tikz 图是 standalone 独立编译成 PDF，底部的长 `\parbox` 文字块会一起进这张 PDF、撑大 bounding box；嵌进论文时 `\includegraphics` 把"主图＋整段文字"当**一张图**缩放，主图被压扁、大段文字游离在图侧/图下——这正是"文字跑到图外面"的根因（真实翻过车：电除尘图把三行 Deutsch–Anderson 公式塞进 `0.92\textwidth` 的 parbox，撑得右下大片是公式、主图被压小）。
   - **判定线（任一条命中就必须挪正文）**：说明 **> 2 行** / **含多行或长公式** / **宽度需 > 主图**。只有**单行极简图例**才可留图下窄 parbox。

```latex
\begin{figure}[H]
\centering
\begin{tikzpicture}
    ...（几何图主体，只留节点/曲线/连线）
\end{tikzpicture}
% 图下只放极简图例(≤2行、窄parbox)；长公式/多行说明写进下方正文，不放这里
\\[2pt]
\parbox{0.5\textwidth}{\footnotesize\centering
    实线：盘入螺线\quad 虚线：等弦长约束\quad ★：最优点
}
\caption{...}
\end{figure}

% ⛔ 长公式推导写在正文段落里（图正下方），不焊进图文件：
% "由 Deutsch–Anderson 分场效率 $\eta_i=1-\exp(-w_{eff,i}A_i/Q)$，四场串联穿透
%  $C_{out}=1000\,C_{in}\prod_{i=1}^4(1-\eta_i)$……" —— 这些是正文的话，不是图的一部分。
```

   - ⛔ 反例一（塞图内）：`\node[align=left] at (S.north east) {$\theta_i=\arg\min\lVert\cdots\rVert^2$ 约束说明……};` — 说明框砸在根节点右上角遮挡主体，`tikz_check.sh` 判 CRITICAL。
   - ⛔ 反例二（满宽长 parbox）：`\parbox{0.92\textwidth}{三行 Deutsch–Anderson 公式……}` 焊在 tikzpicture 后 — 撑大图 bounding box，嵌论文后主图被压扁、文字游离在图侧（本次电除尘图的真实翻车）。
   - ✅ 正例：主图只留节点与连线；图下窄 parbox 只写单行图例；长公式推导写进图正下方的**正文段落**。
   - 仅当说明极短（≤6 字，如单个变量名 `$\theta_0$`）且确有空白区、经确认不压任何节点时，才可留在图内。有疑问一律放正文。

**几何示意图自检清单**（画完后逐条过）：
1. 主曲线颜色 `blue!70!black` 或 `black`？（不是 `violet`/`indigo` 等花哨色）
2. 总颜色数 ≤ 3 种？
3. 所有文字/数字/公式/标签都是**纯黑 `black`（或 ≥black!80）**？绝无红/蓝/彩色文字（强调只用黑体加粗）？没有 `opacity < 0.85` 的文字？
4. 同一焦点附近的标签是否用引线分散？
5. 远端独立标签是否用引线连到对应元素？
6. ⛔【铁律】长公式/多行说明是否已挪进正文（没焊进图文件）？图下 `\parbox` 是否 ≤2 行且宽度 ≤ 主图（没有 0.85~0.92 满宽 parbox）？绝无 `\node at (锚点)` 把说明框塞进图内、压住主体节点？

**必须保持的精致元素**（不管什么配色方案都要有）：
- `drop shadow={opacity=0.15}` 微阴影
- `rounded corners=3pt` 圆角
- `fill=主色!5~!6` 极浅填充（不是纯白也不是深色，参照 6 套配色方案的填充列）
- `line width=0.7pt` 主节点边框粗细
- 子节点 `fill=white`，边框用辅色
- 虚线框统一 `draw=gray!40, dashed, fill=gray!2`（所有配色方案通用，不要变）
- 粗箭头颜色跟主色一致

**鼓励的创意方向**：
- 非对称布局（左重右轻、上密下疏）
- 圆弧箭头、曲线连接（`bend left/right`）
- 渐变色填充（`left color=...!10, right color=...!20`）
- 图标化节点（用简单符号增加辨识度）
- 分组嵌套（大框套小框表示模块层级）
- 时间轴布局（横向时间线 + 上下事件节点）

## ⛔ 零容忍的低级错误（必须避免）

### 编译错误类
- ⛔ 禁止 `on background layer` — 缺少 `backgrounds` 库会导致黑底
- ⛔ 禁止 `fit=()` — 缺少 `fit` 库会编译失败
- ⛔ 禁止未闭合的数学模式 `$` — 每个 `$` 都要有配对
- ⛔ 禁止 `\sout`/`\cancel`/`\xcancel` 在 TikZ 节点内 — 渲染不稳定
- ⛔ 节点内用 `\\` 换行时必须加 `align=center` 或 `align=left` — 否则编译报错
- ⛔ 禁止 `\textbf{}` 在数学模式 `$...$` 内 — 用 `\mathbf{}` 或 `\boldsymbol{}`
- ⛔ 用了 `diamond` 节点必须确保加载了 `shapes.geometric`
- ⛔ 用了 `decorate` 必须确保加载了 `decorations.pathreplacing`

### 视觉灾难类
- ⛔ 禁止灰色大背景 `\fill` — 白底最安全
- ⛔ 禁止浅色文字 — 所有文字（节点内、标注、阶段标签、右侧注释）必须清晰可读。具体禁止：
  - `color=gray!30~70`、`color=主色!20~40`（如 `teal!30`、`blue!25`）— 打印后看不见
  - 右侧注释/阶段标签必须用 `color=black!70` 或更深，不要用 `color=teal!40` 之类的浅色
  - 如果标注文字在白色背景上，颜色深度至少 `!60`（如 `gray!60` 勉强可以，`gray!40` 更安全）
- ⛔ **禁止 `opacity < 0.85` 应用在任何文字/节点/关键箭头**（致命视觉灾难）：
  - 公式说明、辅助标注、坐标点标签等**任何文字** opacity **必须 = 1.0**，不能用 `opacity=0.3` "淡化" 让它看起来 "次要"。这会让评委看不清
  - 唯一允许低 opacity 的场景：**`fill opacity` 用于半透明色块/区域填充**（可行域阴影 `fill opacity=0.3`、光照区域 `fill opacity=0.2`），且这些色块下方**不能有文字**
  - 辅助网格线、参考虚线：`opacity=0.5` + 用 `dashed` + 颜色用 `gray!40` 表达"次要"，**不要靠 opacity 淡化**
  - ⛔ 反例：`\node[opacity=0.3] {等弦长追踪：L²...}` — 公式说明几乎看不见，评委直接负分
  - ✅ 正例：`\node[color=black!75, font=\footnotesize] {等弦长追踪：L²...}` — 颜色稍浅 + 字号小 = 清晰但低调
- ⛔ 禁止白色文字 `text=white` 出现在浅色背景节点上 — 只有深色填充节点（如圆形编号、胶囊标签）才能用白色文字
- ⛔ **禁止把公式/图例说明框用 `\node at (坐标)` 塞进图内挤压主体节点**（致命遮挡灾难）：
  - 长说明框（公式、参数注释、图例）**一律用 `\parbox` 放 `tikzpicture` 之后、`\caption` 之前**，禁止摆到图内角落
  - 尤其禁止相对锚点定位说明框：`\node at (S.north east) {长公式说明}`、`\node at (root.north) {...}` — 宽框会盖住锚点所在的主体节点
  - `tikz_check.sh` 重叠检测已能解析相对锚点 + 按文字估框宽，说明框压节点会被判 CRITICAL，出图必须为 0 CRITICAL
  - 详见上文几何示意图规则第 5 条（铁律）
- ⛔ 反馈/回路箭头必须走空白区域 — 如果底部有标注文字，反馈箭头走上方（`.north` 出发）；如果上方有标题，走下方但要在标注文字下方留足间距
- ⛔ 禁止随机彩虹配色 — 单张图内的配色要有逻辑（按阶段分色或按功能分色），不要每个节点随机一个颜色
- ⛔ 禁止纯蓝/纯红/纯绿高饱和填充 — 用低饱和色（`!10~!15` 填充 + `!50~!60` 边框）

### 重叠类
- ⛔ 节点间隙 >= 0.3cm — 任何两个节点边框不能紧贴或重叠
- ⛔ 中文文字宽度约等于 2 倍英文 — 节点 `minimum width` 和 `text width` 必须按中文字数计算
- ⛔ 侧边标注间距 >= 1.5cm — 多行标注不能重叠
- ⛔ 标注+公式混排用 `text width` — 防止溢出，允许自动换行
- ⛔ 虚线框标签不能和标题重叠 — 垂直间距 >= 0.8cm
- ⛔ 密集连接线不超过 8 条 — 超过时用汇聚节点或省略号
- ⛔ 禁止不透明填充方块遮挡其他元素 — 如果需要标记点/区域，用 `fill opacity=0.3` 或 `draw` 边框而不是实心填充。任何 `\fill` 或 `fill=颜色` 的节点不能覆盖在文字、连线、其他节点上面。如果需要背景色块，用 `on background layer`（需要 `\usetikzlibrary{backgrounds}`）
- ⛔ 标注文字不能挤在一起 — 同一区域的多个标注（如角度 α、法向量 n̂、坐标点）必须错开放置，间距 >= 0.4cm。如果空间不够，用引线（`--` + 小偏移）把标注拉到空白区域

- ⛔ **同一锚点最多 1 个 `above` / `below` / `left` / `right` 方向标签（致命遮挡的根因）**：

  中文标签框默认高度约 7-8pt（含字体行距），即使用 `above=2pt` 偏移，两个标签也会**完全互相覆盖**。这是几何示意图最常见的"质检过了但仍然遮挡"病根。

  **❌ 错误样例（典型病灶：3 个标签贴同一个孔位置 → 互相覆盖成乱码）：**
  ```latex
  \node (h2) at (1.5, 0) [circle, draw] {};
  \node[above=2pt of h2] {第 2 孔};
  \node[above=2pt of h2] {27.5};            % ⛔ 第二个 above 直接覆盖第一个
  \node[above=2pt of h2] {$\varnothing 5.5$};  % ⛔ 第三个再覆盖
  ```

  **✅ 正确做法（散射 + 引线 + 加大偏移）：**
  ```latex
  \node (h2) at (1.5, 0) [circle, draw] {};
  % 主标签放上方且偏移足够大（中文 ≥ 4pt 起步，多字标签用 0.2cm+）
  \node[above=6pt of h2, font=\footnotesize] {第 2 孔};
  % 第二个标签必须散到不同方向（右上）
  \node[above right=10pt and 2pt of h2, font=\scriptsize] {27.5};
  % 第三个标签用引线拉到空白区域
  \draw[gray!60, thin] (h2) -- ++(0.8, 0.6)
        node[right, font=\scriptsize] {$\varnothing 5.5$};
  ```

  **决策树（每加一个标签必走）：**
  1. 同一锚点已有 above 标签 → 第 2 个换 above right / above left（散方向）
  2. 4 个方向（上下左右）都用完 → 第 5 个用引线 `\draw[gray!60, thin] (X) -- ++(dx,dy) node{}` 拉到空白
  3. 中文标签 ≥ 4 字 → 偏移 ≥ 6pt（中文标签框比英文宽且高）
  4. 同区域 ≥ 3 个标签 → **必须** 至少 1 个用引线，不能全堆 above/below

  **⛔ 反模式（永远不要用）：**
  - 多个 `above=Npt of X` 贴同一锚点（N ≤ 4）
  - 多个 `[above]` `[below]` `[left]` `[right]` 不带间距修饰共同贴一节点
  - 一条 `\draw` 路径上挂 ≥ 3 个 `node[label]{}`（路径太短装不下）

### 箭头类
- ⛔ 箭头/连线绝对不能穿过任何节点或文字 — 这是最常见的丑图原因。必须用以下方式绕行：
  - 垂直对齐的节点之间：直接垂直连线，不要从远处斜着拉过来
  - 需要跨行连接时：先垂直走到行间空白区域，再水平拐弯（用 `|-` 或 `-|`）
  - 需要绕过中间节点时：从节点外侧走（`++(偏移)` 先走出去再拐弯）
  - 反馈/跳跃连接：走图的最外侧（左侧或右侧边缘）
- ⛔ 虚线箭头不穿过文字 — 用 `bend left/right` 绕开
- ⛔ 如果两个节点之间有一行工具/方法小节点挡着，连线必须从对应列垂直下来，不要从一个点分叉斜穿

### 尺寸类
- ⛔ 图不能超出页面宽度 — 横向节点超过 5 个时用 `scale=0.8` 或分两行，用 `\adjustbox{max width=\textwidth}` 兜底
- ⛔ 图不能超出页面高度 — 纵向超过 6 个阶段时用 `scale=0.75` 或压缩间距

## 建议（非强制，提升美观度）

### 文字与标签
- 节点内文字用黑色或深灰色
- 左侧标签建议 `color=black`
- 解释性文字（长公式推导、多行参数说明）写在正文里，不要放图里；图下只留单行极简图例（见上方铁律第 5 条）
- 节点文字用 `\footnotesize` 或 `\small`
- 中文标点在节点内尽量避免，用空格或换行代替

### 尺寸控制
- 用 `scale=0.85` 控制大小，不要同时用 scale 和 adjustbox/resizebox
- 阶段数量 4-6 个，每阶段子节点不超过 5 个

### 布局技巧
- 虚线框坐标按公式计算（见 `figure_style_guide.md` 的虚线框坐标计算规则）
- 子节点超过 4 个建议分两行，间距至少 1.2cm
- 侧边标注超过 6 个字符时，用 `text width` + `align=left` 自动换行
- 虚线框标签放在框的左上角外侧，字号用 `\scriptsize`
- 阶段间建议用粗箭头，节点间用细箭头
- 箭头尽量走水平或垂直，拐弯用 `|-` 或 `-|`
- 如果需要表示删除效果，用红色 `\draw` 线条覆盖在节点上方

### preamble 依赖
- 基础：`\usepackage{tikz}` + `\usetikzlibrary{arrows.meta, positioning, shapes.geometric, calc}`
- 大括号装饰需要 `\usetikzlibrary{decorations.pathreplacing}`
- 阴影效果需要 `\usetikzlibrary{shadows}`

### 自检清单（画完后过一遍）
1. 所有数学模式 `$` 都成对闭合了吗？
2. 用了 `\\` 的节点都有 `align=` 属性吗？
3. 用了 `diamond`/`decorate` 的图都加了对应的 `\usetikzlibrary` 吗？
4. 图的总宽度超过 14cm 了吗？超过就加 `scale` 或 `adjustbox`
5. 有没有箭头穿过了不相关的节点？
6. 中文标注的节点 `minimum width` 够宽吗？

### ⛔ 中文节点宽度计算公式（防遮挡核心）

中文字符宽度约为英文的 2 倍。节点宽度必须按以下公式计算：

```
minimum width = 中文字数 × 0.7cm + 英文字符数 × 0.35cm + 1.0cm（内边距）
```

示例：
- "数据预处理"（5 个中文）→ minimum width = 5×0.7 + 1.0 = 4.5cm
- "LSTM 模型"（4 中文 + 4 英文）→ minimum width = 4×0.7 + 4×0.35 + 1.0 = 5.2cm
- "空间杜宾模型 (SDM)"（7 中文 + 5 英文）→ minimum width = 7×0.7 + 5×0.35 + 1.0 = 7.65cm

**⛔ 如果节点文字超过 8 个中文字符，必须用 `text width` + `align=center` 允许自动换行，而不是加大 `minimum width`。**

### ⛔ 编译后自检（必须执行）

TikZ 图写完后，必须编译一次并运行自检脚本：
```bash
# 1. 编译检查 overfull
xelatex -interaction=nonstopmode main.tex 2>&1 | grep -i "overfull\|underfull\|badbox"

# 2. 运行 tikz_check.sh 自动检测（节点重叠+中文宽度+连线穿过+配色）
bash _utils/tikz_check.sh figures/tikz_diagrams.tex 2>/dev/null || bash skills/shared-scripts/tikz_check.sh figures/tikz_diagrams.tex
```

**⛔ tikz_check.sh 报告的所有 CRITICAL 必须修复后重新编译，不允许跳过。** 常见修复：
- 节点重叠 → 调整坐标间距（同行 ≥ 1.0cm，上下 ≥ 0.8cm）
- 中文宽度不足 → 加大 `minimum width` 或用 `text width` + `align=center` 换行
- 连线穿过节点 → 改用 `|-` 或 `-|` 直角拐弯，或加 waypoint 绕行
- Overfull hbox → 缩短文字、加大节点、或用 `\footnotesize`

如果出现 `Overfull \hbox` 警告，说明有文字溢出节点边界，需要：
1. 加大对应节点的 `minimum width` 或 `text width`
2. 缩短节点文字（用缩写）
3. 用 `\footnotesize` 或 `\scriptsize` 缩小字号

**不要忽略 overfull 警告——它就是遮挡的信号。**

### ⛔ 所有 TikZ 图的防遮挡规则 + 精致度要求（模板 4/5/6/7/8/9/10 通用）

**精致度基线（所有 TikZ 图必须达到）**：
- 所有节点必须有 `rounded corners=3pt`
- 主节点必须有 `drop shadow={opacity=0.15, shadow xshift=0.5pt, shadow yshift=-0.5pt}`
- 主节点填充用极浅色（`fill=主色!6`），不是纯白也不是深色
- 子节点/工具节点用 `fill=white` + 辅色边框
- 虚线框用 `draw=gray!40, dashed, fill=gray!2`
- 箭头用 `-stealth`，粗箭头 `line width=1.4pt`，细箭头 `line width=0.5pt`
- **模板 4 的间距标准是所有模板的参考基线**：虚线框 13cm 宽、子节点 x 间距 2.8cm、主节点和子节点 y 间距 1.0cm

技术路线图是遮挡重灾区，因为节点多、层级深。以下规则必须遵守：

**1. 同一行的节点间距 ≥ 1.0cm（边框到边框）**
- 3 个节点一行时，x 坐标间距至少 4cm（如 3, 7, 11）
- 工具/方法小节点一行时，x 坐标间距至少 2.2cm
- 如果一行放不下，分两行，不要硬挤

**2. 上下层之间间距 ≥ 0.8cm**
- 方法节点行 → 工具节点行：y 间距至少 1.0cm
- 工具节点行 → 下一个方法节点行：y 间距至少 1.2cm
- 阶段间粗箭头长度至少 0.6cm

**3. 长文字节点必须加宽或换行**
- "稳健性与内生性检验"（9 个中文）→ 必须用 `text width=4cm` + `align=center`
- 或者缩写为"稳健性检验"（5 个中文）
- 工具节点文字不超过 5 个中文字符

**4. 禁止装饰性元素遮挡内容**
- 不要加灰色大背景 `\fill`（白底最安全）
- 底部方法论标注栏如果和最后一个阶段太近（< 0.5cm），就不要加
- 右侧反馈环虚线如果和输出标签重叠，就不要加
- 卡片背景色必须极浅（RGB 每个通道 ≥ 240），否则节点文字看不清

**5. 模板内容必须契合论文主题**
- 模板中的示例文字（"研究问题提出""数据采集"等）只是占位，必须替换为论文实际内容
- 不要照搬模板的阶段数量——根据论文实际研究步骤增减阶段
- 工具/方法节点只列论文实际使用的方法，不要为了好看而堆砌无关方法名

**6. 连线绝对不能穿过节点（所有 TikZ 图通用）**
- 如果上一行有 3 个方法节点，下面有一行工具节点，再下面有 3 个方法节点，连线必须从上方方法节点的对应列垂直下来，不要从一个节点分叉斜穿工具行
- 正确做法：每列独立垂直连线（spec→mech, ident→hetero, est→ext），不要从 est 一个点分三叉
- 跨行连接走行间空白区域，用 `|-` 或 `-|` 直角拐弯
- 反馈箭头走图的最外侧边缘，不要穿过中间节点

**7. 变量关系图/框架图的防穿过模式（⛔ 最常出错的场景）**

变量关系图（自变量→因变量、控制变量→因变量）是线穿过文字的重灾区。必须遵循：

- **左侧控制变量连到右侧因变量时，不要斜线直连** — 斜线会穿过中间的标注文字和其他节点
- **正确做法 A（推荐）**：控制变量用一个汇聚点，从汇聚点画一条线到因变量
  ```latex
  % 控制变量汇聚后统一连线，不要每个控制变量单独斜线连过去
  \node[circle, fill=gray!30, minimum size=4pt, inner sep=0pt] (ctrl_hub) at (控制变量右侧, 因变量y) {};
  \foreach \x in {ctrl1, ctrl2, ctrl3} { \draw[arrow] (\x.east) -| (ctrl_hub); }
  \draw[arrow] (ctrl_hub) -- (因变量.west);
  ```
- **正确做法 B**：控制变量放在因变量正下方，垂直连线
- **正确做法 C**：控制变量用虚线框框起来，只画一条虚线箭头到因变量，标注"控制"
- **⛔ 错误做法**：3-5 个控制变量各自画一条斜线穿过整个图连到因变量 — 必然穿过中间的文字标注
- **固定效应/时间效应等标注文字**：放在箭头旁边用 `node[above]` 或 `node[below]`，不要放在箭头路径中间被穿过
- **假设标注（H1/H2/H3）**：放在箭头的上方或下方（`node[above, midway]`），不要放在两个节点之间的空白处被其他箭头穿过

**8. 几何示意图的标注防遮挡（⛔ 物理/工程类赛题常见）**

几何示意图（光学反射、传感器布局、力学分析等）的标注密集区域是遮挡重灾区。多个变量标注（坐标、角度、距离、法向量）集中在同一个点附近，必须遵循：

- **标注散射原则**：同一个点附近的多个标注必须分散到不同方向（上/下/左/右/左上/右下），不能都堆在一侧。用 `node[above right=3pt]`、`node[below left=5pt]` 等精确控制偏移
- **引线标注**：如果标注太多放不下，用引线（`\draw[thin, gray] (point) -- ++(0.8,0.5) node[right] {...}`）把标注拉到空白区域
- **标注优先级**：关键变量（如 `R`、`H`、`\alpha`）放在最显眼的位置，次要标注（如坐标 `(x_0, y_0)`）可以放远一些
- **避免标注压在线/面上**：标注文字必须有白色背景（`fill=white, inner sep=1pt`），防止和底下的线条/填充色混在一起
- **角度标注用 arc**：角度 `\alpha`、`\theta` 用 `\draw[->] (point) ++(起始角:半径) arc (起始角:终止角:半径)` 画弧线标注，不要用文字直接放在角的位置
- **距离标注用双头箭头**：`H`、`R`、`d` 等距离用 `\draw[<->]` 双头箭头标注在图形外侧，不要标在图形内部和其他元素重叠

**9. 算法流程图的循环回路防遮挡**

算法流程图（遗传算法/模拟退火/梯度下降等）有循环回路箭头，容易和判断分支标签重叠：

- **循环回路走图的最外侧**：从判断节点的右侧出发（`.east`），向右走到图的最右边缘，再向上回到循环起点。不要从判断节点的左侧走——左侧通常有"否"标签
- **循环回路和判断标签不能在同一侧**：如果"是"标签在下方、"否"标签在右方，循环回路就从右方走；反之亦然
- **循环回路箭头用虚线**：`dashed` 样式区分于主流程的实线，视觉上不抢眼
- **循环次数/终止条件标注**：放在回路箭头的外侧（`node[right, midway]`），不要放在回路内侧和主流程节点重叠

**10. 网络图/拓扑图的边标签防遮挡**

网络图节点密集时，边上的权重/标签容易互相遮挡：

- **边标签用 `auto` 定位**：`node[auto, font=\scriptsize]` 让 TikZ 自动选择标签放在边的哪一侧
- **交叉边用 `bend`**：两条边如果交叉，其中一条用 `bend left=15` 或 `bend right=15` 绕开
- **密集区域只标注关键边**：如果 >8 条边汇聚到一个节点，只标注权重最大/最小的几条，其余省略
- **节点间距至少 2cm**：网络图节点不能太密，`node distance=2cm` 是最低要求

**11. 3D 透视图的标注定位**

3D 透视图（圆柱体/球体/曲面等）的标注需要考虑透视变换：

- **标注放在图形轮廓外侧**：不要把标注放在 3D 物体的"表面上"——透视变换后位置会偏移
- **用引线从轮廓拉出**：`\draw[thin, ->] (surface_point) -- ++(1, 0.5) node[right] {$P_0$}`
- **坐标轴标注放在轴的末端**：`x`/`y`/`z` 轴标签放在箭头末端的外侧，不要放在轴线中间
