## 2. 总体写作观

论文首先是一份让评委快速看懂的模型说明书。语言的价值不在于显得艰深，而在于让读者沿着题目逻辑顺利得到答案。

全文必须遵守四项原则：

1. **以逻辑为主体**：段落、公式、图表和章节都承担明确的信息动作。
2. **语言干练**：不用晦涩词汇、营销词或模型名堆叠制造“高级感”。
3. **面向题目写作**：模型为题目服务，不能把通用算法介绍当成正文主体。
4. **写作与建模交叉推进**：可同步维护骨架、符号、推导说明和临时结果段；最终数字、摘要和结论仍须在证据冻结后定稿。

课程中“用写作拯救未完成模型”的说法只解释为：通过清楚梳理暴露缺口、保留已成立部分并如实限定结论。不得用文字掩盖错误、编造答案或把未验证结果写成事实。

## 3. 贯穿全文的逻辑闭环

### 3.1 三要素

摘要及正文中的每个主要任务单元都应回答：

1. 当前解决什么问题；
2. 为此采用什么方法或实际动作；
3. 得到什么结果或中间输出。

可写成：

> 针对〔具体任务〕，先〔题目对象上的动作〕，再〔模型或求解动作〕，得到〔带对象、数值、单位和条件的结果〕。

这不是固定句式，而是最低信息闭环。只有“采用了某模型”而没有结果，或只有结果而没有说明其对应任务，都属于逻辑断裂。

### 3.2 链式任务

当上一模型的输出是下一模型的输入时，每个子任务按以下顺序写：

`输入与目的 → 处理或模型 → 中间结果 → 传给下一任务的量`

不得连续介绍多个模型，直到章节末尾才一次性给结果。每个步骤的结果应紧跟该步骤出现，使读者能看见模型之间怎样连接。

### 3.3 主题词锚定

模型段落必须持续出现本题对象、变量和决策动作。完成一段后做“遮住标题测试”：

> 如果遮住章节标题，只读该段，能否判断它正在解决哪一道题、处理什么对象？

若只能看出“随机森林、聚类、遗传算法”等通用模型名，而看不出本题对象，则该段属于脱题式算法说明，必须重写。

优先写：

> 将各蔬菜品类的日销量作为聚类对象，以波动幅度和季节性指标刻画销售特征。

避免写：

> K-means 通过迭代更新聚类中心，使类内距离最小。

只有算法的本题改造、关键参数或求解可靠性确实影响答案时，才展开通用算法细节。

## 4. 各板块语言模板

### 4.1 题目

默认优先采用能直接说明研究对象与任务的朴素标题：

- `〔题面主题〕研究`
- `〔对象〕的〔预测/评价/优化/规划〕`
- `〔对象〕的建模与分析`

仅当一至两个核心方法确实贯穿全文、能区分本文方案且不会遮蔽题目对象时，才使用“基于〔方法〕的〔对象/任务〕”。不得把求解器、常用算法或多个模型名堆进标题。

### 4.2 摘要

摘要无公式，采用“总—分—必要时总”的结构。

开头用一至两句完成：

`具体背景或现实矛盾 → 本文需要完成的决策任务`

主体按问题分段，每段都完成：

`问题 → 方法/动作 → 关键结果`

若一问含两级模型，则连续写成两个闭环：

`用方法 A 得到中间量 → 将该中间量输入方法 B → 得到最终答案`

摘要做减法：

- 只保留题目所问的最终结果和决定方案的关键发现；
- 删除中间调试量、运行次数、软件名和不改变结论的细节；
- 不跨题拼接内容，不把问题二的结果挪到问题三；
- 不写“结果很好、利润很高、精度很高”等无基准的主观评价；
- 不强加因果、并列或最优性。

摘要中的重点层级固定执行：每个“针对问题一/二/……”逐问引导语使用黑体加粗；实际出现的算法名、模型名和答案关键词也使用黑体加粗。加粗只覆盖对应短语，不得把完整句子或整段加粗。

摘要收束段只有在存在真实检验、改进或适用边界时才写。不能用“最后评价了模型优缺点”这类无结果句凑尾段。

### 4.3 关键词

关键词通常由三类词组成：

1. 本文研究对象或主题；
2. 真正承担核心作用的模型或方法；
3. 能代表任务或关键指标的高频概念。

控制在一行内，通常 4—6 个。不能全部是算法名，也不能遗漏题目对象。关键词之间只使用空格分隔，不使用中文或英文分号。

### 4.4 问题背景与问题提出

在 `1.1 问题背景` 中，只写与本题矛盾直接相关的事实，通常一小段。采用：

`对象所处情境 → 当前矛盾/需求 → 建模任务`

课程给出的“随着社会与科技发展……具有重要意义”属于占位示例，不得原样使用。没有可靠背景事实时，直接从题面情境起笔，不制造宏大背景。

在 `1.2 问题提出` 中，按小问顺序采用：

`题面给出的对象和规则 → 已知数据与约束 → 逐问需要求出的输出 → 拟采用的宏观建模思路`

使用自己的归纳，不逐句同义替换题面。这里只简要点明每问的建模方向，不展开公式、算法步骤、参数和计算结果。

### 4.5 问题分析

问题分析是模型的设计图，不是摘要，也不是模型正文的缩写。每问按：

`本问要求 → 直接处理的困难 → 关键关系 → 宏观路线 → 预期输出`

不出现最终数值；不展开公式推导和算法参数；不把后文模型复制一遍。可用总体流程图呈现问题之间的依赖，但流程图节点必须替换为本题任务名称，不能保留“任务一、Step 1”等空标签。

### 4.6 模型假设

假设优先来自：

1. 题面明确给出的理想条件；
2. 为建立模型必须作出的、与本题直接相关的简化；
3. 经检验后采用的统计条件。

每条按：

`假设什么 → 为什么能简化 → 不成立时哪部分模型会失效或产生何种偏差`

用“反事实失效测试”检查必要性：若删除该假设后模型和结论完全不受影响，它通常不应列入。

禁止：

- “假设附件数据真实准确”等把本应检查的数据质量问题直接假定掉；
- 未检验就假设正态、独立、同方差、线性或样本足够大；
- 与本题无关的社会热点、流行趋势等凑数假设；
- 大量“忽略不可抗力”式通用兜底。

假设数量不作为质量目标。课程中的“四条左右”只代表控制篇幅的建议，实际数量由模型需要决定。

### 4.7 符号说明

总符号表只保留：

1. 题面对象的主要属性；
2. 模型的主要输入、决策变量和输出；
3. 本文新定义的核心指标。

局部中间变量在使用处解释，不塞入总表。符号即使已在三线表中列出，首次进入正文和公式时仍须就近说明，使读者不必来回翻页。

### 4.8 模型建立与求解

标题最多展开到三级；更细过程用“步骤 1、步骤 2”或短段落组织，避免四级、五级标题。

每一问至少形成：

`模型建立 → 求解或计算 → 结果 → 解释/检验`

物理与机理题按知识关系逐步推导：

`建立对象与坐标/几何关系 → 给出依据 → 写公式 → 解释公式 → 代入或求解 → 展示结果`

必要的受力图、几何图、坐标系和边界示意不能省略。

优化题在“模型建立”内部按：

`决策变量 → 目标函数 → 约束条件 → 模型汇总`

先定义选择什么，再说明优化什么，随后寻找并解释全部约束，最后把变量、目标和约束汇总成完整模型。模型汇总用一句“综上”式短句引出，在同一个显示公式中重列目标函数，并在 `s.t.` 后用纵向大左括号集中列出全部约束和必要状态定义；公式后只用一至两句说明目标、约束类别和可行解含义，不再重复推导。上述四项全部隶属于“模型建立”；完成后再另设同级的“模型求解”和“结果分析”，局部“模型检验”按需设置。不得从算法或求解器起笔。局部检验可不单列，但模型求解、结果和阶段 6 的整体验证不能省略。

数据分析题先增加独立公共数据章，再逐问展开。公共章处理共享的附件关系、合并/查询/透视/筛选/聚合、缺失异常、描述统计和基本数据解释；各问开头仍需按本问字段、样本、时间窗和标签重新准备数据。

每问按课程 `01:10` 后优秀论文的实际排布组织：二级标题对应问题，三级标题对应 Spearman、K-means++ 等本题实际采用的方法；三级标题内部再用 `（1）方法的应用/计算`、`（2）检验/中间结果`、`（3）问题求解` 与正文 Step 展开。公式后紧跟结果表和逐项本题解释，检验结果紧跟检验步骤，随后自然进入下一方法或最终答案。

课程展示的“问题 X 模型流程图”是帮助作者梳理“任务—Step—中间结果”的思维工具，不据此要求每个数据小问在正文插图。本问数据准备也不强制成为单独标题；可在问题开头或首个方法的本题化说明中交代。只有复杂依赖确实难以用上述标题与段落说明时，才把流程图作为可选正文图。通用算法介绍必须服从本题对象：主要篇幅解释它处理什么数据、为何适用、如何计算、得到什么及结果意味着什么。详细结构见 `data-analysis-paper-route.md`。

### 4.9 结果与图表

结果不能只“摆上来”。每个图表后立即完成：

`具体观察 → 形成原因或模型含义 → 对小问答案/下一步决策的作用`

数据分析中的中间结果若将输入下一模型，应明确写出传递关系。大表正文可展示有代表性的行，但必须说明选择规则，完整数据保存在支撑材料；不得只取有利样本或隐藏异常。

### 4.10 模型检验与评价

课程提出的性能测试、灵敏度、稳定性检验和复杂度分析可作为候选，但按题型和证据需要选择，不能机械“选一个”。

优点必须对应具体设计或实验；缺点必须真实说明假设、数据、搜索范围或算法造成的偏差；改进与缺点逐项对应。禁止为了显得安全只写无关痛痒的缺点，禁止无证据宣称“鲁棒性好、普适性强”。

### 4.11 参考文献

引用优先使用学术论文、标准、政府或权威机构资料。个人博客不能作为关键事实和方法正确性的主要证据。引用数量不设人为上限或下限，以正文真实使用为准。

可复现代码、完整结果表、补充图表和过长推导保存在论文外的支撑文件中；关键答案、核心公式和必要解释保留在正文。

## 5. 段落级审查

每个重要段落依次检查：

1. 句首或前两句能否看见本题对象或当前任务；
2. 是否说明为何要做这一步；
3. 专业术语是否落到本题变量和动作上；
4. 方法之后是否紧跟结果或中间输出；
5. 结果是否带对象、条件、数值和单位；
6. 结果之后是否解释意义或后续用途；
7. 是否出现可复制到任意题目的算法教科书段落；
8. 是否用主观褒义词替代比较基准和检验证据。

任何主要段落缺少第 1、4、5 项之一，都应返工。

LaTeX 语言检查时，为 `check_latex_language.py` 重复传入本题对象词，例如：

```powershell
python scripts/check_latex_language.py paper --topic-term 测线 --topic-term 海底 --topic-term 覆盖
```

检查器会拦截篇幅较长、方法词密集但完全没有题目对象的通用算法段落。自动检查只负责发现高风险位置，不能替代人工判断逻辑闭环。

## 6. 课程内容的吸收边界

以下课程观点不升级为强制规则：

- 写作可以掩盖或“拯救”错误模型；
- 背景必须套用宏大万能句；
- 参考文献最好少于十条或可有可无；
- 模型分析与检验只需任选其一；
- 模型评价有字即可；
- 只写无关痛痒的缺点并重点自夸鲁棒性、普适性；
- A/B 题通常只需一个模型、C 题最多三个模型等数量判断；
- 直接复制数据库生成的引用而不核对元数据。

这些说法属于比赛应急教学或经验判断，不能覆盖事实诚信、证据追溯、正式引用和完整验证要求。
