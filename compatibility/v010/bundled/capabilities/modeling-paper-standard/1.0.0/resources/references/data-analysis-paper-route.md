# 数据处理与数据分析类论文路由

## 1. 启用条件

当附件需要合并、查询、透视、筛选、聚合、缺失/异常处理，或不同小问使用不同数据口径，或一问内多个子模型前后依赖时，启用本路由。只有少量数据但不含上述结构时继续使用通用路由。混合题按小问路由。

来源为用户指定视频课程 `00:58:14--00:59:18`、`01:04:45--01:13:20` 的讲稿和屏幕示例，以及用户于 2026-08-02 提供的 `01:10` 优秀论文清晰截图。只吸收组织结构，不复制示例对象、算法、参数或结果。

## 2. 一级结构

数据类完整论文使用：

1. `一、问题重述`
2. `二、问题分析`
3. `三、模型假设`
4. `四、符号说明`
5. `五、数据处理与概览`
6. `六、模型建立与求解`
7. `七、模型检验`
8. `八、模型优缺点评价`
9. `九、参考文献`

“数据处理与概览”可依据实际内容本题化为“数据处理”“数据预处理”或“数据侧写”，但职责不变。该数据类分支来自用户最新明确指令，优先于通用八板块结构。若当届官方模板禁止增加一级章，停止并报告冲突，不得自行合并或改号。

## 3. 第五章职责

第五章只写多个小问共享的数据底座：

- 数据来源、主键、观测单位和表间关系；
- 实际发生的合并、查询、透视、筛选、聚合与重塑；
- 缺失、异常、重复、编码和量纲处理；
- 描述性统计、必要图表及具体数据解释；
- 形成的公共分析表、字段和口径，以及服务哪些小问。

每项按“问题—规则—影响规模—公共输出—后续用途”写。不得列软件操作，不得用假设代替质量检查，不得提前写某一问专属特征。

## 4. 第六章逐问模板

每问使用 `6.n 问题n模型的建立与求解` 或等价本题化标题。内部按实际方法/子任务设置 `6.n.1`、`6.n.2` 等三级标题，不预先强塞“数据准备”和“流程图”标题。

### 课程示例的标准组织

用户指定的优秀论文示例采用：

```text
6.3 问题二：分别建立模型判断关联关系
6.3.1 利用 Spearman 相关系数判断……
（1）Spearman 相关系数的应用
本题对象与采用理由 → 变量与公式 → 相关系数结果表 → 逐项解释
（2）Spearman 相关系数的检验
Step 1 提出假设 → Step 2 计算 P 值 → 检验结果表 → 接受/拒绝判断
6.3.2 通过 K-means++ 聚类算法……
（1）K-means++ 聚类算法的计算
本题特征与参数选择 → Step 1…Step n
（2）得出聚类中心
聚类中心结果表及解释
（3）问题求解
最终分类/关联结果表及直接回答
```

可迁移的是层级和信息动作，不是示例中的蔬菜、算法、参数和结论。

### 本问数据口径

在本问开头或首个方法小节内说明从公共数据取什么、本问新增什么筛选、派生、聚合、标签、时间窗和最终输入。只有这部分内容足够复杂、需要被读者反复引用时，才单列“本问数据准备”三级标题。

### 方法、步骤与结果

每个主要方法或子任务使用一个三级标题。三级标题以下使用 `（1）方法的应用/计算`、`（2）检验/中间结果`、`（3）问题求解`，或 `Step 1/2/3`、步骤一/二、A/B/C 正文标记，不增加第四、第五级数字标题。

每个方法阶段之后立即完成：

`公式/步骤 → 结果表或图 → 具体观察 → 本题解释 → 当前结论 → 下一方法所需输入（若有）`

不得连续介绍多个模型后才集中报结果。算法原理的长度由本题改造和复现需要决定；删除题目对象后仍可原样用于任何论文的教材段落应压缩，围绕本题变量、数据选择、参数、计算和结论的内容必须充分展开。

### 流程图的真实定位

课程中的“问题 X 模型流程图”用于作者或 AI 在写作前梳理 `任务—Step—中间结果`，默认保存为内部写作草图，不是正文强制图。

仅当真实模型链含多分支、循环、回退或跨方法传递，且标题与短段落不足以低成本说明时，才调用 `modeling-flowchart` 制作正文图。若加入正文，节点必须本题化；若不加入，不得因此判论文结构不合格。

### 最终回答

每问末尾汇总已经在各方法阶段产生的答案、代表性验证和边界，不引入新模型或新数字。

## 5. 数据类审稿清单

- 独立公共数据章是否存在，且含规则、规模、输出和解释；
- 每问是否在开头或首个方法小节交代本问数据口径；
- 是否按“问题二级标题—方法三级标题—括号分项/Step—紧邻结果与解释”展开；
- 标题是否止于三级；
- 每个中间结果是否紧跟模型，并说明下一步用途；
- 图表是否有具体观察、解释和答案意义；
- 是否存在脱离题目对象的通用算法段；
- 是否区分共享数据处理与本问专属处理；
- 是否检查标签泄漏、预测时点、划分口径及统计条件；
- 最终回答是否能沿模型链追溯。

## 6. 混合题路由

- 数据输出进入优化时，先按本路由冻结预测/分类/权重/候选集，再将其作为优化输入，并切换到 `optimization-paper-route.md`。
- 含创新算法时，优先用伪代码解释创新核心；只有复杂模块传递确实需要时再加入流程图。
- 简单描述性小问允许缩短模型链，但仍保留“本问数据口径—结果—解释—回答”。
