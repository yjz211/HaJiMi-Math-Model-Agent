# 数学与排版终审契约

本契约适用于新论文、全文重构、局部改写和最终排版。错误可以出现在草稿中，但不得穿过终审后仍被称为终稿。

## 1. 版本状态

论文版本只使用下列状态：

1. `draft`：仍在写作或改图；
2. `candidate`：内容已合并，等待独立审查；
3. `reviewed`：数学、证据、语言和版面审查已通过；
4. `final`：用户人工审阅通过，且最终 PDF 由已审查源码重新编译。

用户人工审阅前不得使用 `final`、最终稿、封板或全部通过等表述。全文重构描述的是交付范围，不允许跳过分章节生产、数学冻结和独立审查。

## 2. 不可自由改写的技术层

进入论文阶段前冻结：

- 核心公式及稳定 `\label`；
- 全局符号、含义、单位和代码变量映射；
- 约束、目标函数、算法停止条件；
- 关键数字及机器可读来源；
- 已验证结论及其适用边界。

数学内容不变的语言或结构重写必须直接复用核心公式环境，不得手工重新录入，不得无理由重命名公式标签。确需修改公式时，退回技术验证，重新运行相关代码、测试和证据冻结。

## 3. 四个维度的独立审查

### 3.1 数学与证据遍

逐问检查：

1. 题面条件、模型假设、公式、代码实现和结果是否一致；
2. 核心公式是否与技术底稿逐式相同；
3. 运算符、正负号、括号、上下标、求和范围和约束方向是否完整；
4. 符号是否一义，符号表、首次定义和后文使用是否一致；
5. 数字、单位、精度和结论强度是否来自冻结证据；
6. 数学退化情形、边界案例或独立实现是否仍支持正文公式。

编译成功、结果数字正确或测试通过均不能替代正文公式核对。使用
`scripts/check_latex_equation_drift.py BASELINE CURRENT` 检查可匹配公式的转写漂移；任何 `FAIL` 必须处理。

### 3.2 写作与图表遍

先按 `plain-competition-language.md` 做独立直白语言审查，再检查固定结构、逐问闭环、摘要无公式和逐图解释。直白语言审查覆盖标题、摘要、正文、答案框、图题、表题和表格文字：逐项清除自创高压缩术语、内部工程简称、高专业性复合标题和连续名词堆叠；标准术语首次出现前先写本题动作；将反复出现的“不能、不得、不代表、不意味着、不应理解为、只能说明”改成观察事实、肯定的适用条件或下一步行动。同一段连续两处防御性否定即为阻断项。改写后必须复核公式、数字、单位、条件和结论范围不变，不能用“肯定写法”制造过度结论。

随后重点确认 `一、问题重述` 下包含 `1.1 问题背景` 与 `1.2 问题提出`：背景简短且不虚构，问题提出逐问概括任务与宏观建模思路；一级标题为 `二、问题分析` 时，其逐问二级标题使用 `2.n`，不得沿用原始样张笔误 `1.n`。优化类小问还要检查层级与信息完整性：“决策变量—目标函数—约束条件—模型汇总”必须按序全部位于“模型建立”内部，“模型求解”和“结果分析”是随后同级的小节，不得把六项平铺为同一级标题；四个 Step 只能作为正文步骤标记，不能继续建立第四级标题。模型汇总必须在同一个显示公式中重列目标，并在 `s.t.` 后以大左括号收拢全部约束和必要定义；逐项核对前三步与汇总式的变量、目标、约束、方向和索引是否一致。局部模型检验标题可以省略，但不得借此省略结果可信度和阶段 6 验证。另检查摘要中每个逐问引导语以及算法名、模型名、答案关键词是否按规定黑体加粗，并检查关键词是否仅以空格分隔。图前目的、图后观察、原因和意义是语义动作，不是固定句式；不得为每幅图重复“这张图的用途是”“要回答的问题是”等元话语。核心几何关系难以仅凭公式理解时，优先增加一幅合并示意图，而不是继续增加结果图。

模型建立表达另做来源路由检查：成熟模型组合是否需要用流程图清楚展示输入、模块职责、中间量传递、耦合关系和输出；创新算法是否需要用伪代码说明输入输出、初始化、核心更新、分支/循环与终止条件。流程图与伪代码均按信息增益选择，不因课程思维草图或形式完整而强制加入正文；一旦采用，必须映射真实模型而非内部工作流，也不能替代数学定义和证据。

数据处理/数据分析类论文另做专门结构检查：是否在符号说明后设置独立公共数据章并顺延后续编号；公共章是否给出共享处理的规则、影响规模、输出和数据解释；每问是否交代专属数据口径；是否按“问题二级标题—方法三级标题—括号分项/Step—紧邻结果与解释”组织；多模型存在依赖时是否说明中间结果用途；是否止于三级标题。不得把本问数据准备标题或逐问流程图作为固定门槛。

优化类论文除层级和汇总式外，还要按 `optimization-paper-route.md` 检查内容密度：Step 1 是否按变量组写清对象、符号、索引、类型、单位、取值域和方案作用；Step 2 是否拆解目标组成并解释来源、量纲、符号方向、权重/惩罚和合成方式；Step 3 是否让每一类约束都形成“现实规则—数学表达—索引/单位—边界含义”的完整单元。模型求解须写清算法适配、模型映射、初始化/参数、可行性处理及停止条件；结果须给出方案、目标组成、约束满足和必要比较。“模型汇总式后一两句”不得被误用为整个优化章节的压缩规则。必须建立“题面条件—数学表达—变量—代码位置—验证证据”覆盖矩阵，并按矩阵确认的约束行数调用 `check_latex_structure.py --optimization-question 问题号 --optimization-constraint-min 问题号:行数`；未提供矩阵行数即视为阻断项。检查器的语义覆盖通过后仍要人工核对真实性，正文推导、汇总式和代码约束须逐项闭合，不能用关键词或两三条示意约束冒充完整模型。

运行 `scripts/check_section_balance.py MODEL_TEX VALIDATION_TEX EVALUATION_TEX`。“模型检验＋模型优缺点评价”相对“模型建立与求解”的可见中文叙述量超过 30% 即为阻断项。人工同步检查 PDF 页幅和阅读重心，确认没有把检验改名后移入模型段、用密排规避比例，或为了补页增加不改变结论的诊断。

### 3.3 LaTeX 源码版面遍

检查：

- 手工标题与环境自动标题是否重复；
- 参考文献和一级标题是否只出现一次；
- `[H]` 是否过度使用并造成浮动体拥塞；
- `\newpage`、`\clearpage` 是否有必要；
- 图题、表题、公式标签和交叉引用是否唯一；
- 摘要、参考文献的环境是否与可见标题相容。
- 优化模型的 `Step 4` 标记、引导句与总括公式是否被分页拆开。

运行 `scripts/check_latex_layout_risks.py MAIN_TEX`。阻断项必须清零；警告项必须逐项人工判断并在 QA 记录中说明。

### 3.4 最终 PDF 版面遍

先用接触图检查整体节奏，再以至少 150 dpi 或实际阅读尺寸逐页检查。接触图只能发现宏观问题，不算逐页终审。

逐页检查：

1. 页首是否以残句、单字或上一页断开的短语开始；
2. 页末是否只剩标题、短句或被截断的语义单元；
3. 是否存在孤行、孤标题、中文词组难看断开；
4. 是否出现大面积无理由留白或连续页面密度失衡；
5. 公式运算符、编号和括号在实际尺寸下是否完整；
6. 图表、图例、坐标、题注是否遮挡、跨页或与正文脱节；
7. 参考文献和页码是否重复、缺失或层级异常。

运行 `scripts/check_pdf_page_flow.py FINAL_PDF` 获取重复标题、页首残句和页面低密度候选。脚本只提供风险线索，不能替代全尺寸人工阅读。

## 4. 修订后的回归检查

- 修改公式：重跑相关代码、测试、公式漂移检查、数字映射和受影响章节；
- 修改全局符号：检查全文和符号表；
- 修改标题、字体、行距或浮动策略：重新渲染全部页面；
- 修改局部段落或单图：重新检查受影响页面及前后一页；
- 修改参考文献环境：检查标题、引用和论文结束位置。

四个维度针对同一候选分别判断，汇总问题后集中修订，不为每个维度重写全文。审查对象必须是冻结的 `candidate`。发现问题后修订，再生成新的候选版本；不得一边审查一边继续扩写。

## 5. 终稿放行条件

只有同时满足下列条件才可申请用户人工审阅：

- 数学与证据遍无未解决问题；
- 结构和语言检查通过；
- 高压缩词、防御性句式和人工逐段复核均已记录；不存在自动检查漏掉的自创晦涩复合词；
- LaTeX 源码版面检查无阻断项；
- PDF 正文 22--30 页门槛通过；
- 已核对“篇幅—论证”关系：没有为达到页数重复背景、拆碎段落、放大图表或塞入长代码，也没有因追求短小而省略关键推导、图表解释、验证或边界；
- 章节篇幅平衡检查通过：模型检验与模型优缺点评价合计不超过模型建立与求解的 30%，且短论文的新增篇幅优先来自真实模型推导、求解细节和结果解释；
- 不存在单个图、表或流程图独占或近乎独占一页；`check_pdf_large_float.py` 无阻断项，所有图表均与对应引入、推导或解释形成紧凑页面；
- 最终 PDF 已按实际尺寸逐页阅读；
- 页面流警告均已处理或记录合理理由；
- QA 记录包含检查对象哈希、检查结果、人工判断和遗留边界。
