# 直观竞赛语言规则

本文件与 `plain-competition-language.md` 配套执行。直观语言不是把科研术语换成另一套缩写，而是让评委直接看到对象、动作、结果和使用方法。

## 1. 核心顺序

按以下顺序组织第一阅读层：

`题目对象 → 实际动作 → 关键结果 → 直观解释 → 代表性验证 → 适用边界 → 必要术语`

严谨内容不删除，只调整层级。摘要、问题分析、结果段和结论优先使用前五项；完整定义、实现细节和复现信息放在模型、检验或论文外的支撑文件。

## 2. 各板块句式

### 摘要

- “针对问题一，为得到……，先……，再……。结果表明……。”
- “对问题二，在问题一的基础上……，得到……。”
- “对问题三，从……开始，逐条……，最终……；该结果适用于……范围。”

不得在摘要中放公式、软件名、文件名、哈希、程序断言数或密集的搜索规模。
每一问必须同时出现问题、方法/动作和结果。只有“建立……模型”“采用……算法”而没有答案的段落不得通过。

### 问题重述

- `1.1 问题背景`：先用几句话写系统或对象在现实中如何工作，以及存在什么直接需求或矛盾；
- `1.2 问题提出`：再按小问顺序写题目要求得到什么，并用一句直观语言点明各问拟采用的宏观建模思路；
- 不在问题提出中展开公式、算法细节、参数和计算结果。

不写行业审计流程，不引用内部证据管理方式。

### 问题分析

- “本问要求……。关键在于……。因此先……，再……，最后……。”
- 对优化题，优先把目标翻译成选择顺序或可执行动作。

### 模型与算法

- 公式前：“为计算/约束……，先定义……。”
- 公式后：“该式表明……增大时，……会……，因此布线时需要……。”
- 算法：“确定方向 → 贴边放置首线 → 更新间距 → 检查边界 → 输出方案。”
- 优化类小问：在“模型建立”内部写“定义要选择的变量 → 写明优化目标 → 逐类建立约束 → 汇总完整模型”；模型汇总以“综上，〔对象〕的优化模型为”引出，在同一个公式中重列目标函数，并在 `s.t.` 后用大左括号收拢全部约束和必要定义，式后只解释一两句。完成模型建立后，再另设“模型求解”和“结果分析”。局部模型检验按需要设置，不为凑结构强制单列。

每段至少出现一个本题对象词或决策动作。若把“蔬菜、测线、板凳龙、工件”等对象词全部删掉后段落仍毫无变化，说明它过度通用，应改写为本题化叙述。

### 结果与图表

- “图 X 用于判断……。”
- “可以看到……；这是因为……；因此方案应……。”
- “最终得到……，满足……，但只在……条件下成立。”

### 模型检验

- “为检查公式是否正确/路线是否漏测/结论是否稳定，我们……。”
- “结果……，因此支持……。该结论适用于……范围。”

### 优缺点与结论

- 优点写“哪项设计带来什么作用”；
- 缺点写“哪项假设可能造成什么偏差”；
- 改进写“增加什么信息或成本后能改善什么”；
- 结论按问题逐项回答，用行动、数字、验证和边界收束。

## 3. 术语翻译

| 技术或审计表达 | 第一阅读层写法 |
|---|---|
| 首线相位 | 第一条覆盖带从边界的哪个位置开始 |
| 字典序目标 | 先排除漏测，再减少过度重叠，最后缩短总航程 |
| 自适应间距 | 浅水处收紧测线，深水处适当放宽 |
| 独立射线复核 | 重新计算波束边缘与海底的交点 |
| 未检出正间隙 | 在给定分辨率下没有发现条带空隙 |
| 有限族最优 | 在已比较的平行测线方案中最短 |
| 证据链、可追溯 | 正文写具体公式、结果或检验；证据管理词移出主叙事 |
| 事实审计、冻结结果 | 移入内部审稿或支撑材料，不进入论文正文 |
| 程序断言、哈希、运行命令 | 移入论文外的复现说明 |

## 4. 高压缩与防御性表达改写

| 避免使用 | 直接写法 |
|---|---|
| 冻结模型 | 在查看测试结果前确定模型 |
| 支持域、域内、域外 | 有相近实测数据的范围、在该范围内、超出该范围 |
| 发布、拒识、门控 | 给出结果、转入校准、按条件进入下一步 |
| 正式层、探索层 | 实测方案选择、下一批试验建议 |
| 回填 | 用完整试验结果更新早期判断 |
| 代理发布门槛 | 预测模型优于简单基准后再提出新方案 |
| 不能直接用于新对象 | 新对象先完成校准，再使用模型 |
| 不能证明普遍成立 | 结论适用于当前样本和参数范围 |
| 不能称为已验证最优 | 方案进入下一轮验证，验证完成后更新方案集合 |

高压缩词在代码、内部审查和交接记录中可以保留；进入标题、摘要、正文、图题、表格或答案框时必须展开。必要的数学术语先用一句日常语言说明它在本题中做什么，再给正式名称。

## 5. 段落自检

逐段询问：

1. 句首能否看见题目对象或要解决的问题？
2. 专业术语之前是否已有直观动作？
3. 关键数字后是否解释了趋势、原因或决策意义？
4. 是否把内部生产过程误写成论文内容？
5. 删除验证计数后，最强证据是否仍清楚？
6. 简化语言后，结论范围是否仍准确？
7. 是否存在需要读者自行拆解的自创复合词或连续专业名词？
8. 能否把否定句改成明确的事实、适用条件或下一步行动？

## 6. 来源与边界

- 共同最高来源：用户指定的 2026 Word 模板与论文写作视频课程。前者主控结构和版式，后者重点用于语言闭环、主题词锚定和分题型叙述。
- 印证来源：用户授权的 B311、B477、B226 正文共同写法。
- 真实反例：`practice_002` W0 中摘要、问题分析、验证和结论的审计性表达。
- 真实演进证据：`practice_009` 先把“冻结模型、支持域、拒识、正式层/探索层、回填、代理发布门槛”等压缩词展开，再逐句修订 121 处防御性表达；该题只用于语言规则，不迁移模型与数字。

不吸收展示论文中的摘要公式、算法名堆叠、无证据自评或缺少搜索范围的“最优”。本规则只约束表达顺序，不改变任何题目的模型、数字和证据等级。
