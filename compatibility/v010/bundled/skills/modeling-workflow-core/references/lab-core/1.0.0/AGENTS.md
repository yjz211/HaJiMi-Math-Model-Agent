# MathModeling AI Lab 项目规则

## 项目目标

在顶尖 AI 辅助下，持续训练数学建模问题分析、模型探索、程序求解、结果验证、论文写作和审稿能力，逐步形成可复用、可验证的工作系统。

## 开始任务前

1. 读取根目录 `CURRENT_TASK.md`，确认当前题目路径。
2. 读取根目录 `MEMORY.md` 和当前题目的 `STATUS.md`、`TASKS.md`。
3. 只读取与当前任务有关的文件；默认不要读取其他题目的最终答案。
4. 如果原题或关键附件缺失，停止建模并明确报告缺失项。
5. 不得调用与当前任务无关的长期职业规划或个人偏好 Skill，除非用户明确要求。

## 训练轨道开关

1. 每道新题默认使用 `training_track: full`、`paper_training: enabled` 和 `completion_target: paper_complete`，完整走完阶段 0—9。
2. 阶段 0—7 仍必须先完成建模、程序、验证、最小证据、模型与代码审查；只有证据冻结后才能启动阶段 8 的完整论文、图表精修和最终排版。
3. 用户明确要求“只练求解”时，才可改用 `training_track: solver` 和 `paper_training: disabled`；关闭论文不等于省略模型说明或证据。
4. 总控必须在 `CURRENT_TASK.md` 和题目 `STATUS.md` 记录该题的轨道、论文开关、完成目标及变更原因。
5. 关闭论文的题目使用 `solver_complete`；完整论文轨道只有在阶段 9 的用户人工审查与资源对标复盘完成后才可使用 `paper_complete`。

## 事实与证据

1. 明确区分原题事实、人工假设、模型推断和计算结果。
2. 不得编造数据、文献、引用、实验结果或竞赛规则。
3. 所有关键数字必须能够追溯到代码、参数、运行记录和结果文件。
4. 未经验证的临时结果不得进入论文定稿。
5. 外部资料必须保存来源、访问日期及其支持的具体结论。
6. 阶段 0 材料审计和阶段 1 题意定义通过后、阶段 3 基线开始前，阶段 2 默认开展建模前文献预研：自主检索权威背景、标准、综述、通用模型、评价指标和验证方法，并保存来源登记与预研报告。
7. 建模前文献预研不得搜索、打开或使用本届本题的竞赛解答、优秀论文、成品论文、博客解法、视频、代码仓库或答案数字；意外发现时只记录“发现但未读取”。同题优秀论文仍只能在主要求解与验证完成后由用户提供或明确授权。
8. 文献中的事实、参数和方法不得自动覆盖题面事实或成为本题数据；引入外部数据、重大假设或最终模型路线仍须用户确认。

## 建模要求

1. 每个小问先明确输入、输出、目标、变量和约束。
2. 重要问题至少提出一个简单基线和两个候选改进方案。
3. 选择模型时比较正确性、可解释性、数据要求、求解成本和验证难度。
4. 复杂模型必须说明相对于基线解决了什么问题。
5. 所有假设必须说明理由、影响和适用边界。
6. 阶段 4 默认采用逐问交叉模式：按小问依赖顺序依次完成“建模分析—基线与候选比较—原型代码—路线确认—正式实现—局部测试与结果—人工检查点”。代码能运行不能替代候选比较，也不能据此过早锁定模型。
7. 阶段 4 开始前必须先冻结全题共用的题意、数据政策、公共假设、变量符号、评价口径和小问依赖；每问完成后向用户提交简洁审查包。所有小问均完成且重大路线得到确认后，阶段 4 才能通过。
8. 阶段 5 固定为整题集成与联合审查：重新直接核对原题和逐问覆盖矩阵，检查跨问依赖、共享数据、符号、单位、假设、参数和结论是否一致，运行整题统一入口与集成测试。发现问题时返回对应的阶段 1—4，不得在阶段 5 静默修改目标或模型。
9. 阶段 5 的联合审查不替代阶段 6 的独立验证、敏感性与稳健性，也不替代阶段 7 的正式模型审查、代码审查和证据冻结。

## 编程与验证

1. 代码必须实际运行，不得仅凭阅读声称正确。
2. 关键算法至少完成一个可手算的小规模案例。
3. 检查边界输入、极端参数、单位、约束、守恒关系和随机种子。
4. 关键结果尽量使用替代实现、枚举或独立方法交叉验证。
5. 原始结果与论文展示结果分开保存，不得手工改写关键数字。

## 论文要求

本节只在当前题目的 `paper_training: enabled` 时执行；开关关闭时不得自行启动完整论文生产。

论文技术检查（数字追溯、源码预检、版面渲染）属于阶段 8 的交付验证；阶段 9 由用户人工审查论文并提供/授权优秀论文资源，总控据此完成对标复盘和用户明确指出的修订，不独立设置阶段 10。

1. 论文必须逐问给出明确回答。
2. 论文中的数值只能来自 `results/evidence_manifest.md` 或对应的机器可读结果。
3. 表格字段中文化、单位明确、小数位统一；程序原始字段和浮点尾差不得进入正文。
4. 删除重复扩写、空洞背景、内部工作流、文件路径和无证据评价。
5. 摘要最后撰写，摘要中的每个关键数字必须能在正文和证据表中找到。
6. 附录应提供真正有复现价值的代码、算法或补充结果。
7. 论文主流程固定使用 LaTeX 源码编译 PDF。每次创建、改写、排版或审查论文时必须调用个人 Skill `modeling-paper-standard`，严格执行用户指定 2026 模板的板块顺序、大小编号、套路化写作和最终版面；参考文件是 Word 不意味着改用 DOCX。启动论文阶段前同时读取 `methodology/latex_paper_workflow.md` 与 `methodology/paper_training_2026_reference.md`。若当届可核实的强制提交规则与模板冲突，停止并向用户报告冲突，不得静默改动模板或交付格式。
8. 正式图表统一使用项目内 `modeling-plot-suite`，并读取其项目绘图契约与 `modeling-paper-standard/references/figure-integration-contract.md`。先定义信息目的、证据来源和视觉规范，再逐图选择：定量数据、真实几何构型、地图和网络结果走 `paper-figure`；解析物理/工程几何优先走 HTML/TikZ；总览、模型组合、算法、决策和验证流程默认走 HTML，需要对象级编辑时走 Draw.io，简单文本原生图走 Mermaid；生成式插画只在用户明确要求时走内置 ImageGen，且不得替代定量或精确工程证据。每张图独立选择单图或多子图：一个坐标系、几何对象、热力图或临界构型已能支撑结论时优先单图；只有多个面板回答不同问题、必须共同支撑同一结论且最终尺寸仍清晰时才组合。不得用重复图、固定九宫格、空面板、图例专用面板或装饰图凑数量。中文读者标签默认用中文，数学符号、SI 单位、通用缩写和正式专名按规范保留；使用经验证的中文无衬线字体，最终字号通常保持在 8.5—10 pt。保存数据/语义来源、可编辑源或生成脚本、主输出和 QA，完成实际成图、最终尺寸及整页审美判断；检查器通过不代表美观，常规美化不得推给用户。当届模板与官方格式优先。
9. 旧式 `.doc` 参考模板的结构和版式审计以 Microsoft Word 原生渲染为主证据；LibreOffice 只作兼容性检查。正式论文仍由 LaTeX 生成，并以最终 PDF 对照模板验收。复用绘图仓库的代码、图片或示例前分别核对许可证与素材来源，不把示例资产直接当论文素材。
10. 每篇 `paper_training: enabled` 的完整论文至少包含一张高质量总览流程图，优先作为问题分析或总体建模路线的阅读引导；使用项目内 `modeling-plot-suite`，默认选择 HTML 流程图，需要对象级编辑时选择 Draw.io，简单文本原生图可选择 Mermaid。流程图必须映射真实的问题分解、模型、求解、验证和逐问输出，与数据图和工程图共享字体、语义色板、线宽和最终尺寸 QA，保留可编辑源与 SVG/PDF 矢量主文件，不得把内部 Agent 工作流画进论文。只有在流程图会实质性误导极简单论文时，才可记录理由并经用户明确同意后豁免；其他流程图仍按信息需要决定，不为数量添加。
11. 摘要不得出现公式或独立数学推导；每一张正文图都必须被正文引用，并在图前说明用途、图后给出具体观察、解释与对答案的意义。只放图题或只写“由图可知”不得通过论文验收。
12. 模型建立采用表达路由：已有成熟模型的组合、串联或迁移运用，强烈推荐用 `modeling-plot-suite` 的确定性流程图工作流展示输入、模型职责、中间量传递、耦合与输出；高度创新的自研代码或算法，优先在模型建立部分加入简洁伪代码，说明输入输出、初始化、核心更新、分支/循环和终止条件；混合路线可用流程图讲结构、伪代码讲创新模块。不得重复同一内容，也不得用图或伪代码替代数学定义、公式和验证。
13. 正文从摘要至参考文献必须为 22--30 页，附录不计入；达到最低页数只能补充真实推导、算法、比较、结果解释、验证、敏感性、边界和可追溯图表。禁止单个图、表或流程图独占或近乎独占一页，也不得通过放大图表凑页。
14. 数据处理/数据分析类论文必须读取 `modeling-paper-standard` 的 `data-analysis-paper-route.md`，采用独立公共数据章与逐问方法链结构：公共章写共享的数据整合、质量处理、描述统计和输出；每问在开头或首个方法小节交代专属数据口径，按“问题二级标题—方法三级标题—括号分项/Step—紧邻结果与解释—下一方法或最终求解”展开，标题止于三级。视频中的模型流程图默认是写作前思维草图，不是逐问正文硬门槛；只在确实降低复杂依赖的理解成本时加入。该分支将模型建立与求解及后续一级编号顺延；若当届官方格式禁止增加一级章，停止并报告冲突。
15. 优化类论文必须读取 `modeling-paper-standard` 的 `optimization-paper-route.md`。四个 Step 只规定“决策变量—目标函数—约束条件—模型汇总”的组织顺序，不限制篇幅，也不得机械写成四个等长短段。Step 1 按变量组写对象、符号、索引、类型、单位、取值域和方案作用；Step 2 拆解目标组成并解释来源、量纲、方向、权重/惩罚和合成方式；Step 3 对每类约束形成“现实规则—数学表达—索引/单位—边界含义”，通常是展开最多的部分；Step 4 完整集中汇总。必须建立“题面条件—数学表达—变量—代码位置—验证证据”约束覆盖矩阵，并将矩阵确认的约束行数传给结构检查器。模型求解必须交代算法适配、模型映射、初始化/参数、可行性处理和停止条件；结果分析必须报告可执行方案、目标组成、约束满足及比较、稳定性或最优性边界。只有模型汇总处的重复说明保持简短，不得把“一两句说明”扩展为整个优化章节的压缩要求。
16. 论文语言以竞赛评委快速阅读为目标，必须执行 `modeling-paper-standard` 的 `plain-competition-language.md`。标题、摘要、正文、答案框、图题和表格文字禁止自创晦涩的高压缩词、内部工程简称、连续专业名词和科研论文式名词堆叠；“冻结模型、支持域、拒识、门控、正式层/探索层、回填、代理发布门槛”等必须展开为题目对象、实际动作、条件和结果。标准术语确有必要时先用直白语言说明其本题作用，再给名称。结论优先用肯定句写清观察事实、适用条件和下一步行动，不得反复使用“不能、不得、不代表、不意味着、不应理解为、只能说明”作防御性兜底；改写不得删除失败结果、单位、假设或证据边界。

## Agent 协作

1. 每个 Agent 只能修改任务中明确分配的文件。
2. 并行 Agent 默认写入当前题目的 `workstreams/<角色>/`。
3. 不得覆盖其他 Agent 的产物；发现冲突时先停止并报告。
4. 写操作较多的任务不要让多个 Agent 同时修改同一文件。
5. Agent 完成任务后必须提交 `HANDOFF.md`，说明结论、证据、不确定性、修改文件和下一步。
6. 只有总控任务负责确认模型路线、合并正式结果和更新项目状态。

## 经验更新

1. 每道题结束后必须完成 `review/retrospective.md`。
2. 第一次出现的问题先记录在本题复盘中，不立即升级为通用规则。
3. 只有具有证据且可能跨题复用的经验，才能写入根目录 `MEMORY.md`。
4. 同类错误重复出现后，优先增加自动检查或测试，而不是只增加文字提醒。
5. 修改长期规则时记录原因和来源题目。
6. 阶段 9 的优秀论文对标只读取用户人工提供或明确授权的资料；记录阅读范围、吸收项、不适用边界与来源，不读取其附录代码或其他解答材料，除非用户另行授权。

## 完成标准

任务只有在产物已保存、关键结果已验证、未解决问题已记录、相关状态文件已更新后才算完成。
