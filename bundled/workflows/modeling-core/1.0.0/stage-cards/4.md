# 阶段 4：逐问建模与代码求解
按问题依赖组织求解，保留多路线探索、模型比较和交叉验证。路线存在实质不确定性时，选择有代表性的候选方法，使用共同数据与评价口径进行实验比较，再按结果选择或组合方法。不要为了节省流程开销省略有价值的实验。
关键建模结果可以换方法验证：例如解析推导与数值计算互证、不同算法或独立实现复算、小规模枚举、已知解与边界测试、交叉验证、敏感性和稳健性分析。方法间不一致时定位数据、假设、实现或适用范围的原因，必要时继续迭代；结果收敛且已有充分证据后停止无新增信息的重复验证。
模型自主决定候选数量、验证方法、实验顺序和迭代深度，向用户解释依据。代码、参数、指标、图表和有信息量的失败结果直接保存在工作区即可；无需逐项创建 QuestionWorkPacket、Evidence、Claim、哈希冻结或路线门。阶段结束一次总结各问结果、方法比较和重要验证发现。半自动在阶段报告后等待用户意见，按需发起的问题讨论不要求技术登记。
