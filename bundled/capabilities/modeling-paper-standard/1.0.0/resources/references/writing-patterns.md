# 模板写作套路

这些套路规定每一板块必须完成的信息动作，不提供可直接粘贴的空话。

全文先执行 `plain-competition-language.md`：使用竞赛说明书式的通俗直白语言，不使用高压缩科研词汇或大量防御性否定。先写对象、动作和结果，再写必要模型名与范围；真实边界改写为肯定的适用条件或下一步行动。

## 题目

默认优先采用直接说明研究对象与任务的朴素标题，如“〔对象〕的建模与分析”“〔对象〕的〔预测/评价/优化/规划〕”。只有一至两个核心方法确实贯穿全文并能区分本文方案时，才采用“基于〔方法〕的〔对象或问题〕”。不得把求解器、常用算法或多个模型名堆入题目。

## 摘要三段式

摘要中不得出现公式、公式环境或独立数学推导。模型关系用准确的自然语言概括，只保留理解方法与结果所必需的变量名、指标名和数值。

### 第一段：背景与问题

依次完成：

1. 用一至两句压缩背景；
2. 指出现实矛盾或决策难点；
3. 明确本文需要解决的全部小问。

### 第二段：方法与结果

按小问顺序重复“问题—方法/动作—结果”：

- 针对什么问题；
- 建立或采用什么模型；
- 完成什么计算、优化、预测或评价动作；
- 得到什么关键量化结果。

这一段是摘要主体。结果必须具体，模型名只在帮助理解时出现。

每一问都必须闭环。若一问先预测再优化，应先写预测得到的中间量，再说明该量如何进入优化模型，最后给出最终答案，不能连续报出两个模型名后省略结果。

摘要主体按题号分成独立自然段。每个自然段必须以“针对问题一/二/……”或等价逐问引导语排头，并且只回答对应的一问；禁止为了压缩篇幅而把两问或多问连续写在同一自然段。

每问优先使用显式题号，并先写工程动作。例如先写“从边界放置第一条测线，再逐条调整间距”，再说明这是边界相位搜索或自适应递推。搜索步长、候选数量、运行次数、软件名和内部检查名通常不进入摘要。

摘要的重点层级按以下规则统一：

- 每一问开头的“针对问题一”“针对问题二”或等价逐问引导语必须使用黑体加粗；
- 摘要中实际出现的算法名称、模型名称和承载最终答案的关键词必须使用黑体加粗；
- 加粗只作用于上述短语，不把完整句子或整段摘要大面积加粗；
- 关键词行中的各关键词只用空格分隔，不使用中文分号 `；` 或英文分号 `;`。

### 第三段：检验、价值与边界

依次完成：

1. 总结真正有证据的设计亮点或主要判断；
2. 给出误差、稳定性、灵敏度或交叉验证结论；
3. 说明可推广价值与适用边界。

没有真实检验或边界信息时可以省略单独的收束段。不能用“最后评价了模型优缺点”“精度很高、鲁棒性强、普适性极强”代替结果。

## 问题重述

固定拆为两个二级小节。

### 1.1 问题背景

用几句话交代研究对象在现实生活或实际业务中的应用情境、直接需求与矛盾。背景应短、准、与本题有关；没有可靠的题外事实时，只依据题面情境概括，不写“意义重大”等空泛扩写。

### 1.2 问题提出

按题目小问顺序，用简单直观的语言说明：

1. 每一问需要解决什么；
2. 已知的关键数据、规则或约束是什么；
3. 拟采用什么宏观建模思路；
4. 最终需要输出什么指标、方案或结论。

这里只点明方案，不展开公式、算法步骤、参数和结果；路线选择的理由、困难与变量关系放在“二、问题分析”中。

控制在半页至一页。用自己的语言概括，不逐句替换同义词。

背景采用“具体情境—现实矛盾—建模任务”，只保留本题所需事实。不得照搬“随着社会与科技发展……具有重要意义”等万能占位句。

## 问题分析

每个小问使用“要求—难点—关系—路线”的套路：

1. 这一问要求什么；
2. 真正困难在哪里；
3. 变量、约束或数据之间有什么关系；
4. 因此采用怎样的建模与验证路线。

各小问分析完成后，用总体流程图汇总问题分解、模型、求解、验证和输出之间的关系。

语言顺序固定为“题目要求什么—直接做为什么困难—先做什么—再做什么—得到什么输出”。不得以算法清单、内部审计流程或术语定义代替问题分析。

问题分析不写最终数值，不复制摘要，也不提前展开公式和算法参数。它是路线图，不是结果汇报。

## 模型假设

每条假设使用“假设内容—采用理由—影响边界”的套路：

1. 明确假设对象；
2. 说明为何可以简化；
3. 说明该假设会影响哪些结论以及何时失效。

只写模型实际使用的假设。禁止照搬模板中的平稳性、真实性、合理性等示例标签。

对每条假设执行反事实失效测试：若假设不成立，明确哪条公式、约束或结论会失效。若删除后模型完全不受影响，通常不应列入。正态、独立、同方差、线性等统计条件必须先检验，不能用“假设”代替数据诊断。

## 符号说明

先用三线表给出主要全局符号、含义和单位，再在符号首次进入正文时解释。局部临时变量不塞入总符号表。

## 模型建立与求解

每个小问遵循以下闭环：

1. 数据预处理：来源、缺失、异常、转换和单位；
2. 模型建立：目标、变量、关系、约束、公式和假设；
3. 模型求解：算法、参数、停止条件和实现；
4. 模型检验：正确性、误差、边界或替代方法；
5. 结果分析：直接回答小问，解释现实含义。

若题型不需要某一动作，可以省略对应三级标题，但不得省略模型、求解、答案和可信度说明。

标题最多到三级，更细过程用“步骤 1、步骤 2”组织。模型段执行主题词锚定：本题对象、变量或决策动作必须持续可见；通用算法原理最多简述一小段。链式模型按“输入与目的—方法—中间结果—下一步用途”逐段推进。

### 优化类问题的固定展开

优化类小问先设置三级标题“模型建立”。该部分内部按以下顺序组织：

1. **决策变量**：说明要选择什么，给出变量含义、类型、单位、索引和取值域；
2. **目标函数**：说明优化什么、方向为何是最大化或最小化，以及各项如何由题意得到；
3. **约束条件**：逐类给出资源、物理、逻辑、边界、拓扑、时间或业务约束，并解释其现实含义；
4. **模型汇总**：把决策变量、目标函数、全部约束和必要的状态定义汇总为一个完整的标准优化模型，明确可行域与必要参数。

以上四项全部隶属于“模型建立”，统一用 `Step 1` 至 `Step 4` 的黑体正文步骤标记组织，不新增标题层级，也不能与后续三级标题并列。完成模型建立后，再依次设置：

1. **模型求解**：说明求解算法、初始化、参数、停止条件、可行性维护和实现方式；
2. **结果分析**：给出方案、目标值、约束满足情况、代价和对小问的直接回答；
3. **模型检验（可选）**：只在需要时检查可行性、最优性证据、边界或替代方案，不强制设置独立标题。

不得先介绍求解器或算法，再补写决策变量和目标；不得把分散在正文各处的约束留给读者自行拼接。

这四个 Step 只规定顺序，不限制篇幅。Step 1—3 必须承载变量体系、目标推导和分类约束的完整论证；“汇总式后只写一两句”只约束 Step 4 的重复说明。模型求解不得只写求解器名称，应交代算法适配理由、变量编码或模型映射、初始化/关键参数、可行性维护、停止条件和返回方案复原。结果分析不得只报目标值，应给出决策方案、目标组成、约束满足/松弛、基线或候选比较以及直接题目回答。完整路由见 `optimization-paper-route.md`。

模型汇总使用以下视觉与语义结构：

```latex
综上，〔本题对象〕的优化模型为
\begin{equation}
\begin{aligned}
\min_{\boldsymbol{x}}\quad & f(\boldsymbol{x})\\
\text{s.t.}\quad &
\left\{
\begin{aligned}
g_i(\boldsymbol{x})&\le 0, && i\in\mathcal I,\\
h_j(\boldsymbol{x})&=0, && j\in\mathcal J,\\
\boldsymbol{x}&\in\mathcal X.
\end{aligned}
\right.
\end{aligned}
\end{equation}
```

目标函数与约束必须处于同一个显示公式中；`s.t.` 后用一个纵向大左括号收拢全部约束。若目标或约束依赖状态方程、运动关系、递推式或布尔判定，应把这些必要定义一并放入大括号；中间推导、解释性公式和候选模型比较仍留在前三步，不塞入汇总式。汇总式只负责“集中再现”，不引入新数学内容。

写完后执行对应性检查：

1. Step 1 中每个决策变量都在目标、约束或可行域中出现，并具有类型或范围；
2. Step 2 的优化方向和目标表达式与汇总式完全一致；
3. Step 3 中实际采用的每条约束都进入大括号，符号和不等号方向不变；
4. 汇总式中的每个符号都已在前文或符号表定义；
5. 汇总式前用一句话引出，式后用一至两句说明目标、约束类别和可行解含义，不重复逐式推导。

模型汇总不是机械抄写，而是给出一次完整的数学模型，使评委能在一个位置看清“选择什么、优化什么、受什么限制、怎样才算可行”。局部检验可省略标题，但答案可信度仍须由第五节的必要说明或第六节的整体验证支撑。

### 数据处理与数据分析类问题的固定展开

数据类完整论文在符号说明后单设“数据处理与概览”，只写多个小问共享的附件关系、整合/重塑、质量处理、描述统计、图表解释和公共输出。每项处理按“数据问题—规则—影响规模—输出—后续用途”形成闭环；不得只写软件操作，也不得用假设替代异常和缺失检查。

模型建立与求解顺延为第六章。参考课程 `01:10` 后的优秀论文示例，每问按实际方法设置三级标题，并在方法内部交错呈现：

`方法为何适用本题 →（1）方法的应用/计算 → 本题变量与公式 → 结果表及具体解释 →（2）必要检验或下一方法 → Step → 中间结果 →（3）问题求解`

本问新增的字段、样本、时间窗、派生、聚合、标签和输入写在本问开头或首个方法小节；内容较多时才单设“本问数据准备”，不得为形式完整制造空标题。每个子模型的结果、图表解释及下一步用途必须紧跟其后，不能把全部结果拖到问题末尾。

课程画出的“问题 X 模型流程图”默认用于作者/AI 在写作前梳理任务、步骤和中间结果。只有真实模型链包含难以用标题和短段落说清的分支、循环或多阶段传递，且流程图能显著降低阅读成本时，才使用 `modeling-flowchart` 加入正文；不得逐问机械配图。详细执行与混合题路由见 `data-analysis-paper-route.md`。

### 推导展开与篇幅来源

正文长度必须来自读者完成复核所需的信息，不来自预设页数。每个关键模型按实际需要展开：

1. 先用题目对象说明坐标、状态、时间线、集合或决策变量，必要时配几何图或机理图；
2. 从原题条件和已声明假设逐步推出关系式，说明每个关键等式为何成立，不把多步推导压成“显然可得”；
3. 在关键公式后解释符号、单位、适用条件和物理或决策含义；
4. 给出可实现的求解步骤、停止条件或分支逻辑；复杂迭代、搜索、回退和多阶段依赖可在对应小节加入局部流程图；
5. 报告中间结果如何进入下一步，并用表、图或文字解释最终答案及其可信度；
6. 只保留与本题对象相关的推导，不扩写通用算法教材、软件操作或无证据背景。

正文必须达到 22 页，因此论文偏短时应按上述论证链逐项查找真实缺口，并优先补齐可复核推导、候选比较、结果解释、验证、敏感性和边界。不得为了达到页数重复问题背景、拆碎段落、放大图表或堆入长代码。

篇幅不足时按以下顺序补充，不能把模型检验当作默认扩页区：

1. 补齐从题面条件到模型关系式的推导过程；
2. 解释关键公式中每个量的来源、单位、方向和适用条件；
3. 展开求解算法的输入、更新、停止条件、复杂度和中间结果传递；
4. 增加候选模型为何被选择或淘汰的本题化比较；
5. 补充最终结果的误差结构、机理解释和逐问答案；
6. 只有存在真实证据缺口时才增加新的检验。

必要时增加模型结构图、变量关系图、算法流程图或关键结果图，但图必须减少文字难以表达的理解成本，不能作为扩页装饰。模型建立与求解的篇幅应显著大于检验与评价。

### 图表与流程图的章节配置

总览流程图负责全文导航，局部图表负责解决具体理解障碍。可按论证需要在模型建立、算法设计、结果分析和验证章节配置：

- 几何或机理图：说明空间关系、运动阶段、边界和变量定义；
- 局部算法/决策流程图：说明分支、循环、临界搜索、失败回退或多阶段依赖；
- 定量结果图：展示趋势、比较、分区、极值或方案差异；
- 验证与敏感性图：展示误差、收敛、扰动响应或稳健性。

不要求每个小问机械配图，也不限制流程图只能出现在问题分析。每张图必须对应一个文字难以低成本表达的关系；若删除后不影响理解和判断，应删除。正文中必须让图表与其引入、步骤或解释形成紧凑页面，禁止单图、单表或单流程图独占或近乎独占整页。

### 模型建立的流程图与伪代码路由

不按题型机械决定是否画流程图，而按模型来源和读者的理解成本选择：

1. **成熟模型的组合与运用**：强烈推荐在模型建立部分绘制流程图。节点写清输入数据或状态、各成熟模型承担的本题任务、模型间传递的中间量、耦合/反馈关系和最终输出；不得只列模型名称，也不得画内部 Agent 分工。使用 `modeling-flowchart`，保留可编辑矢量源并完成最终论文页面检查。该图只有在覆盖全题问题分解、求解、验证与输出时，才能同时充当全文总览图；否则它是局部模型流程图。
2. **高度创新的自研代码或算法**：优先在模型建立部分给出短小伪代码，写明输入、输出、初始化、核心状态更新、关键分支/循环和终止条件。伪代码描述算法思想，不复制编程语言语法、库调用、文件路径或调试代码。
3. **成熟框架与创新模块并存**：用流程图解释模块关系和信息传递，用伪代码解释真正创新且仅靠框图无法复现的核心模块；两者不得重复同一层信息。

流程图和伪代码都是理解辅助，不能替代变量定义、数学关系、假设、约束、复杂度说明和结果验证。若成熟模型只有一个、调用关系非常简单，一小段文字已足够，则不为“形式完整”强行增加局部流程图；若创新仅体现在参数调整而非算法机制，也不包装成伪代码。

## 图的解释套路

每一张图都必须在正文中被引用并得到对应解释，强制完成：

1. 图前说明为什么需要这张图、希望回答什么问题；
2. 图后指出可见的关键趋势、差异、极值、分区或异常；
3. 解释该现象对模型、决策或小问答案意味着什么；
4. 必要时说明单位、条件、误差和适用边界。

四项缺一即视为图文论证不合格，不得进入定稿。不得只插图和图题，也不得只写“由图可知”而不说明具体观察。

图注负责说明图中对象，正文负责完成判断。不能把全部解释塞入长图注而正文不显式引用。

上述四项是语义动作，不是固定句式。不得让多幅图连续使用“这张图的用途是”“要回答的问题是”“图 X 专门展示”等元话语。优先让图自然进入推导，例如先提出判断，再引用图并直接写观察、原因和结论。全文终审需搜索重复图表引导句，出现机械复用时返工。

## 模型检验

按题型选用，不机械凑齐：

- 预测或拟合：误差指标、残差、外推边界；
- 优化：可行性、最优性证据、替代方案；
- 评价：权重扰动、排序稳定性、方法对照；
- 多参数模型：灵敏度分析；
- 随机模型：重复实验、置信区间、随机种子；
- 通用要求：极端输入、单位、守恒、约束和独立复核。

写作顺序为“检验目的—设置—指标—结果—判断—边界”。

检验段从“要确认什么”开头，不从“几层证据体系、审计闭环或程序是否通过”开头。哈希、命令、断言数和构建记录放入支撑材料。

正文通常只保留“主要泛化表现＋一项关键稳健性/敏感性＋必要的失败诊断”。校准、随机种子、分层结果、复算流程和证据映射只有在直接改变答案时才展开，否则压缩为一句或移入论文外的支撑文件。第五节的局部检验、第六节的集中检验和第七节的评价不得重复同一数字与边界。第六、七节的可见中文叙述量合计不得超过第五节的 30%。

## 模型优缺点评价

### 优点

从简洁性、可解释性、计算效率、数据要求、验证强度和实际可执行性中选择有证据的条目。每个优点必须指出对应设计或实验。

### 缺点

明确受什么假设、数据、参数、算法或算力限制，以及可能导致什么偏差。不能只写“仍有提升空间”。

### 改进

逐项对应缺点，说明增加什么数据、替换什么模型、放松什么假设或采用什么算法，并说明预期改善与新增成本。
