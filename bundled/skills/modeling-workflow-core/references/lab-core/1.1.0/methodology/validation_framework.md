# 程序、结果与论文证据链框架

> 状态：第 0 步 C 已完成初版研究和模板落地，尚待第 0 步 E 微型案例端到端检验。

## 一、核心原则

“程序成功退出”只说明它没有在当前路径上崩溃，不说明模型正确、数据处理合理或结论可信。每个关键结论必须经过以下链条：

`原题事实 → 数据与假设 → 模型表达 → 可运行程序 → 原始结果 → 独立验证 → 证据表 → 论文表述`

链条中任一环节缺失，结果只能标记为临时结果，不能进入论文定稿。

## 二、运行前输入契约

每个小问开始编程前必须固定：

1. `problem/problem_spec.md` 中的输入、输出、目标、变量、约束和单位；
2. 原始附件的文件名、大小和哈希值，原始数据只读保存；
3. 数据字典、缺失和异常处理策略；
4. 采用的模型版本、核心假设和基线；
5. 配置文件、随机种子、运行命令和软件依赖；
6. 预期生成的机器可读结果、图像和检查项。

若字段、单位、目标或约束仍不明确，停止写最终求解代码，返回题意或数据审计阶段。

## 三、六级验证门

| 级别 | 检查内容 | 最低证据 | 未通过时的动作 |
|---|---|---|---|
| V0 静态与输入检查 | 语法、依赖、路径、字段、类型、单位、缺失、重复 | 环境与数据质量记录 | 修复环境或数据契约，不解释模型结果 |
| V1 最小可手算案例 | 选取能人工计算或穷举的小问题 | 手算过程与程序输出对照 | 修正公式、索引、方向或边界 |
| V2 不变量与边界 | 守恒、约束、概率和、非负性、极端输入、空输入 | 自动测试或断言记录 | 结果保持 `unverified` |
| V3 独立交叉验证 | 替代实现、精确枚举、另一求解器、基线或理论解 | 两种方法的差异表 | 查明差异来源，禁止挑选有利结果 |
| V4 稳健性与泛化 | 未见数据、结构化切分、参数敏感性、扰动、场景变化 | 指标分布、区间或稳定性图表 | 缩小结论边界或更换模型 |
| V5 复现与证据冻结 | 干净环境重跑，论文数字逐项追溯 | 运行清单、结果哈希、证据表和独立审查 | 不允许进入论文定稿 |

关键算法至少达到 V1、V2 和 V5；关键结论尽量达到 V3 和 V4。无法执行某一级时，必须记录原因及替代证据，不得默认为通过。

## 四、按任务类型选择验证方式

| 任务 | 必做检查 | 推荐交叉验证 |
|---|---|---|
| 回归/分类 | 朴素基线、泄漏检查、训练外评价、适合任务的指标 | 替代模型、分组/分层交叉验证、误差分层 |
| 时间序列 | 朴素或季节朴素基线、严格前推切分、预测区间 | 滚动起点评价、结构突变情景、残差诊断 |
| 聚类/降维 | 标准化依据、距离含义、类别稳定性 | 重采样稳定性、不同初始化、领域解释 |
| 评价与排序 | 指标方向、量纲、权重依据、排名稳定性 | 替代归一化、权重扰动、删减指标测试 |
| 优化 | 每条约束可行性、目标值复算、求解状态和 gap | 小规模穷举、松弛界、另一求解器或构造性上/下界 |
| 微分方程/仿真 | 初值边界、守恒、步长、单位、随机种子 | 解析特例、步长收敛、重复试验、替代积分器 |
| 蒙特卡洛/风险 | 分布来源、样本量、种子、收敛 | 多种子重复、置信区间、分布与情景敏感性 |

敏感性分析不能机械固定为“所有参数 ±10% 或 ±20%”。扰动范围应来自测量误差、政策范围、工程容差、文献区间或明确的情景假设。

## 五、运行记录

每次可能影响论文结论的运行都保存一份运行清单，字段见 `templates/case-template/experiments/run_manifest_template.yaml`。至少包含：

- 唯一 `run_id`、开始时间、操作者或 Agent；
- 实际命令、入口程序、退出码和运行时长；
- 输入文件及哈希、配置文件、随机种子；
- Python/MATLAB 与关键依赖版本；
- Git 提交号和工作区是否有未提交修改；
- 输出文件、哈希和验证状态；
- 异常、警告及其是否影响结论。

临时探索允许简化记录，但一旦结果被候选论文引用，就必须补齐正式运行清单并从头重跑。

## 六、文件分层

- `problem/original/`：原题和原始附件，只读，不手工覆盖。
- `experiments/configs/`：参数、情景和随机种子。
- `experiments/raw_results/`：机器原始输出和运行日志，不为论文手工改数。
- `results/tables/`：由程序生成并格式化的论文候选表格。
- `results/figures/`：由程序生成的论文候选图片。
- `results/evidence_manifest.md`：论文关键数字与原始结果、程序、配置和验证证据的索引。
- `paper/`：只消费已经进入证据表的结果，不反向创造计算结果。

原始结果和展示结果必须分开。中文表头、小数位和图形美化应由可复现脚本完成。

## 七、证据状态

| 状态 | 含义 | 是否可进论文 |
|---|---|---|
| `unverified` | 只生成了结果 | 否 |
| `checked` | 通过 V0–V2 基本检查 | 仅可进入明确标注的工作草稿 |
| `cross_validated` | 通过适用的 V3/V4 | 可进入论文候选稿 |
| `frozen` | V5 复现、来源锁定并经独立审查 | 可进入论文定稿 |

状态按“结论”而不是按整个脚本统一授予。同一运行中的一个指标可冻结，另一个仍可能未验证。

## 八、论文引用门

论文中的每个关键数值必须在 `results/evidence_manifest.md` 中登记：

1. 对应题目和结论；
2. 原始机器可读结果中的字段或单元；
3. 生成脚本、运行 ID、配置和种子；
4. 单位、精度与展示变换；
5. 验证方法、证据文件和状态；
6. 论文中的章节、表号或图号。

摘要只能在正文结论已经冻结后撰写。若论文数字无法反查到机器结果，删除该数字或重新运行，不允许凭记忆补写。

## 九、返工条件

出现以下任一情况，立即退回相应阶段：

- 运行成功但手算例不一致；
- 约束、守恒、单位或边界检查失败；
- 训练与测试泄漏，或时间/群组切分错误；
- 启发式结果没有基线、界或重复试验支撑；
- 更换随机种子、参数或实现后结论方向改变；
- 论文图表无法定位生成脚本和运行 ID；
- 环境或依赖无法从运行说明复现；
- AI 生成了未实际运行的数字、图表或“结果分析”。

## 十、本轮本地代码给出的验证证据

本地“14 种必备算法”示例证明了分层验证的必要性：首次运行只有 7 个文件成功，补齐依赖后 16 个均能运行；这说明依赖问题与算法问题必须分开。进一步检查中，蚁群 TSP 输出与 10 城市精确枚举一致，而 NSGA-II 示例的非支配排序在三点手算案例上给出了错误等级。详细记录见 `local_reference_review.md`。
